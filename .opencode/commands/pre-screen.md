# Быстрое предварительное скринирование статьи

Оцени базовые сигналы качества статьи без полного рецензирования. Подходит для:
- пакетного отбора статей для решения, какую рецензировать первой
- самопроверки статьи перед подачей (соответствие требованиям мероприятия)
- быстрой оценки «уровня» статьи

> **Оркестрация:** выполняй по секции «/pre-screen» в `${OPENCODE_HARNESS_ROOT}/shared/paper-review-orchestration.md`: только `paper-analyzer` → `quick-assess.py`, без полного цикла. Контракты — в `shared/paper-review-chain-contracts.md`. Путь к PDF: <pdf_path>.

Аргументы: `$ARGUMENTS`

## Шаг 1: разбор текста статьи

Предпочтительно через MCP, fallback — прямое чтение PDF:
1. `mcp__paper-parser__parse_paper` (или Read постранично)
2. Сохрани разобранный текст во временный файл

## Шаг 2: запуск скрипта быстрой оценки

```
python "${OPENCODE_HARNESS_ROOT}/scripts/paper-review/quick-assess.py" <файл_с_текстом>
```

Скрипт вернёт JSON: тип статьи, свежесть цитирований, полноту структуры, анонимность, статистическую строгость, наличие метрик эффективности, соблюдение чек-листа мероприятия.

## Шаг 3: форматированный отчёт

Преобразуй JSON в читаемый вид:

```markdown
# Отчёт предварительного скрининга

**Статья**: [название]
**Целевое мероприятие**: [venue]
**Дата скрининга**: [дата]

## Сигналы качества

| Показатель | Результат | Статус |
|------|------|------|
| Тип статьи | экспериментальная | - |
| Свежесть цитирований | доля за 2 года 25% | ✅ хорошо |
| Полнота структуры | 78% (нет Limitations) | ⚠️ почти полная |
| Анонимность | нарушений нет | ✅ ок |
| Статистическая строгость | есть error bars | ✅ есть |
| Метрики эффективности | FLOPs и FPS | ✅ есть |

## Сводка сигналов
- ✅ × N
- ⚠️ × N

## Предварительная оценка
[1–2 предложения о «уровне» статьи]

## Рекомендации
[На что обратить внимание при полном рецензировании]
```

## Шаг 4: проверка соответствия мероприятию (если задан `--venue`)

Дополнительно проверь:
- обязательный чек-лист мероприятия (см. `${OPENCODE_HARNESS_ROOT}/skills/opencode-current/paper-review/references/venue-profiles.md`)
- требования к формату (лимит страниц и т.п.)
- отсутствие важных для этого мероприятия разделов

Сохрани отчёт как `PreScreen_<название_статьи>.md`.

## Примечания

- Команда делает только поверхностную проверку качества, **не оценивает содержание** (без проверки формул и сравнения с SOTA).
- Время выполнения: < 1 минуты.
- Подходит как предварительный шаг перед `/review-paper`.
