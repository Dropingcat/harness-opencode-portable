# Помощь с Rebuttal

Помоги автору системно ответить на замечания рецензентов. Поддерживаются два режима.

> **Оркестрация:** выполняй по секции «/rebuttal» в `${OPENCODE_HARNESS_ROOT}/shared/paper-review-orchestration.md` — без диспатча субагентов цепочки (это не рецензирование); работаешь сам, режим A или B по параметрам.

## Определение режима

- **Режим A (написание Rebuttal)**: задан только файл с замечаниями → пошаговый разбор и подготовка ответов.
- **Режим B (проверка исправлений)**: заданы замечания + исправленная статья → проверка каждой реплики, достаточно ли полно отвечает.

## Разбор аргументов

Аргументы: `$ARGUMENTS`

- `<review_file>` — файл с замечаниями рецензентов (Markdown / текст / PDF), обязательно
- `[revised_pdf]` — исправленная статья (опционально, режим B)
- `--original <original_pdf>` — исходная версия (опционально, для сравнения изменений)

## Режим A: написание Rebuttal

### Шаг 1: разбор замечаний

Извлеки структурированную информацию из файла замечаний:
1. Определи реплики каждого рецензента
2. Извлеки все Weakness (W1, W2, …)
3. Извлеки все Questions (Q1, Q2, …)
4. Извлеки оценки и рекомендации по приёму
5. Раздели Major и Minor проблемы

### Шаг 2: классификация и приоритизация

Раздели все проблемы на четыре типа:

| Тип | Описание | Стратегия ответа |
|------|------|---------|
| **Можно ответить сразу** | недопонимание рецензента или уже описанное в статье | сослаться на конкретное место в статье |
| **Нужны доп. эксперименты** | отсутствует сравнение/абляция | описать планируемые эксперименты и ожидаемый результат |
| **Нужна правка статьи** | проблемы написания, формата, ссылок | описать конкретный план правок |
| **Принципиальное возражение** | сомнение в методе/мотивации | самый полный и убедительный ответ |

Сортируй по влиянию: принципиальные возражения > доп. эксперименты > правки > прямые ответы.

### Шаг 3: черновик ответа по каждой реплике

Для каждой Weakness и Question подготовь черновик:

```markdown
## Ответ рецензенту #X

### W1: [кратко суть замечания]

**Ответ**: [содержание ответа]

**Предпринятые действия**: [конкретные правки с указанием мест в статье]
```

Принципы ответов:
1. **Сначала благодарность**: поблагодари за конструктивные замечания.
2. **Без уклонений**: отвечай на каждый вопрос прямо.
3. **С доказательствами**: каждый ответ подкрепляй фактами (экспериментальные данные, ссылки, выводы формул).
4. **С указанием мест**: правки отмечай конкретно (например, «Section 3.2, Eq.5»).
5. **Без споров**: даже при недопонимании отвечай фактами и данными спокойно.

### Шаг 4: итоговый документ Rebuttal

Выведи полный документ, сохрани как `Rebuttal_<название_статьи>.md`:

```markdown
# Rebuttal

We thank all reviewers for their constructive feedback.

## Summary of Changes
[обзор основных правок]

## Response to Reviewer #1
### W1: ...
### Q1: ...

## Response to Reviewer #2
...

## Additional Experiments (if applicable)
[таблица дополнительных экспериментов]
```

### Шаг 5: рекомендации по дополнительным экспериментам

Если рецензенты требуют доп. эксперименты:
1. Перечисли все требуемые эксперименты
2. Оцени выполнимость и ожидаемое время каждого
3. Для выполнимых — предложи дизайн эксперимента
4. Для невыполнимых — подготовь обоснованное объяснение

### Шаг 2: разбор исправленной статьи

Используй `mcp__paper-parser__parse_paper` или Read для разбора исправленной статьи. Если задан `--original` — сравни изменения.

### Шаг 3: проверка по каждой реплике

Для каждой Weakness и Question:
1. Найди в исправленной статье соответствующие правки
2. Оцени, достаточно ли полно отвечает правка
3. Отметь статус:

| Статус | Описание |
|------|------|
| ✅ отвечено полностью | в статье есть явная и достаточная правка |
| ⚠️ отвечено частично | есть правка, но недостаточная |
| ❌ не отвечено | в статье нет соответствующей правки |
| ℹ️ правка не нужна | мелкое замечание, не влияет на статью |

### Шаг 4: отчёт о проверке

```markdown
# Отчёт о проверке исправлений

## Общий статус
- Всего замечаний: X
- Отвечено полностью: X (✅)
- Отвечено частично: X (⚠️)
- Не отвечено: X (❌)
- Правка не нужна: X (ℹ️)

## Детальная проверка
### Рецензент #1
| Замечание | Статус | Доказательство в исправленной статье |
|-------|--------|--------------------------|
| W1    | ✅     | Section 3.2, новая Table 5 |
| W2    | ⚠️     | Правка есть, но неполная   |
| Q1    | ❌     | Не найдено                 |
```

Сохрани как `Revision_Check_<название_статьи>.md`.
