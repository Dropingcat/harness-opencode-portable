# Автоматическое рецензирование статьи

Выполни профессиональное рецензирование академической статьи по 4 фазам и выведи структурированный отчёт. Поддерживается адаптация под целевое мероприятие (CVPR/NeurIPS/ICML/ICLR/ECCV/ICCV/ACL/AAAI/KDD/MICCAI и др.).

> **Источник истины для оркестрации:** следуй `${OPENCODE_HARNESS_ROOT}/shared/paper-review-orchestration.md` (порядок фаз, диспатч субагентов, merge по контракту 5) и `${OPENCODE_HARNESS_ROOT}/shared/paper-review-chain-contracts.md` (шаблоны JSON и acceptance). Этот файл — краткая справка-входная точка.

## Разбор аргументов

Аргументы команды: `$ARGUMENTS`

- `<pdf_path>` — путь к PDF статьи (обязательно)
- `--venue <конференция>` — целевое мероприятие/журнал (опционально)
- `--with-code <каталог>` — каталог исходного кода (опционально, включает ревизию кода)
- `--with-supplement <pdf>` — PDF дополнительных материалов (опционально)

Если `--venue` не указан — спроси пользователя о целевом мероприятии. Убедись, что PDF существует, прежде чем начинать.

## Адаптация под мероприятие

По `--venue` загрузи соответствующий профиль из `${OPENCODE_HARNESS_ROOT}/skills/opencode-current/paper-review/references/venue-profiles.md` и `venue-review-criteria.md`:
- скорректируй веса критериев (ICML — теория, CVPR — визуальное качество, ACL — LLM-базлайны и т.д.)
- загрузи чек-лист мероприятия
- используй критерии оценки и ориентиры по acceptance rate
- задай ожидаемые базлайны и датасеты

Перспективы рецензентов (если есть для venue): `${OPENCODE_HARNESS_ROOT}/docs/reviewer-perspectives/01-cvpr-reviewer.md` … `10-miccai-reviewer.md`.

## Фаза 1: парсинг статьи

**Способ A (предпочтительно) — MCP `paper-parser`:**

1. `mcp__paper-parser__parse_paper` — разбор PDF в Markdown
2. `mcp__paper-parser__extract_references` — извлечение списка литературы
3. `mcp__paper-parser__extract_figures_and_tables` — извлечение рисунков/таблиц/формул в PNG
4. Если есть supplementary PDF — разбери и его
5. Прочитай извлечённые изображения (Read) для визуального анализа

**Способ B (fallback) — прямое чтение PDF:**

Если MCP недоступен: читай PDF постранично (до 20 страниц за вызов), анализируй рисунки/формулы визуально, извлекай список литературы вручную.

**Автодетекция:** сначала вызови `mcp__paper-parser__ping`; при успехе — способ A, при ошибке/таймауте — способ B и сообщи пользователю.

Сохрани всё извлечённое для следующих фаз.

## Фаза 1.5: быстрая оценка (Quick Assessment)

Запусти скрипт количественной оценки:

```
python "${OPENCODE_HARNESS_ROOT}/scripts/paper-review/quick-assess.py" <файл_с_текстом_статьи>
```

Скрипт детектирует: тип статьи (теоретическая/экспериментальная/прикладная/системная), свежесть цитирований (доля за 2 года, медианный год), полноту структуры (Abstract…References), анонимность (GitHub-ссылки, «our previous work»), статистическую строгость (±, error bars, тесты, доверительные интервалы, random seed), эффективность (Params/FLOPs/FPS/память/время обучения), соблюдение чек-листа мероприятия.

**Вывод:** первое впечатление + количественные индикаторы + рекомендации по фокусу Фазы 2.

## Фаза 2: параллельное многомерное рецензирование

Запусти субагентов harness через Task, каждый получает текст статьи и связанные данные. Используй агентов:

- **`paper-analyzer`** — разбор PDF (если не сделано в Фазе 1)
- **`technical-reviewer`** — техническая корректность, формулы, эксперименты, статистика, сравнение с SOTA (агенты B–C оригинала)
- **`reference-auditor`** — related work, верификация ссылок, поиск пропущенных цитат (агент E)
- **`paper-comparator`** — сравнение с конкурирующими работами

Покрываемые измерения (в соответствии с `references/scoring-guide.md`):

1. **Аннотация, мотивация и новизна** — обоснованность пробела, формальные определения, новизна vs комбинация известного, соответствие заявленных вкладов содержанию.
2. **Техническая корректность** — математическая корректность формул (области значений, согласованность символов), полнота определений, явность допущений, логические противоречия.
3. **Эксперименты и статистическая строгость** — актуальность базлайнов (сверка с SOTA через `mcp__academic-search__get_sota_results` / `find_competing_methods`), честность сравнения (одинаковые условия, скрытые «удачные» настройки), полнота абляций, статистическая значимость, отчёт об эффективности.
4. **Качество написания и воспроизводимость** — грамматика, согласованность символов, полнота related work, достаточность деталей для воспроизведения, полнота выводов и ограничений.
5. **Related work и аудит ссылок** — `mcp__academic-search__verify_references_batch`, `find_missing_citations`, `search_related_work`; поиск высокоцитируемых работ за последние 12 месяцев; выявление несоответствия «цитата ⇄ содержание»; список 5–10 наиболее релевантных последних работ с пометкой «процитировано/нет».
6. **Код (если `--with-code`)** — системное чтение исходников, сверка формул с реализацией, поиск нераскрытых приёмов обучения, расхождения «статья ⇄ код» (активации, веса потерь, архитектура, оптимизатор, гиперпараметры).

## Фаза 3: генерация отчёта

Объедини результаты всех фаз в стандартный формат рецензии.

Шаблон: `${OPENCODE_HARNESS_ROOT}/skills/opencode-current/paper-review/references/review-template.md`
Критерии оценки: `references/scoring-guide.md`
Профили мероприятий: `references/venue-profiles.md`

Отчёт должен содержать:
- первое впечатление (Фаза 1.5)
- детальное многомерное рецензирование (Фаза 2)
- ревизию кода (если применимо)
- уверенность рецензента (1–5)
- маппинг оценок под мероприятие (если задан `--venue`)
- meta-review резюме

Сохрани отчёт рядом с PDF: `Review_Report_<название_статьи>.md` и покажи его пользователю.
