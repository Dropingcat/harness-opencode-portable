# Task & Context Assessment — оценка задачи и контекста перед поиском (TD-177)

Контракт глубины: `shared/search-depth-contract.md` (TD-170). Этот skill — шаг «оценить задачу и контекст» цикла **зафиксировать → осмотреться → оценить глубину → идти дальше**.

## Когда использовать

Вызывается ПЕРЕД началом поиска (до `unified_search` и любых каналов):

- «оцени задачу» / «оцени контекст»;
- «что искать?» / «какую глубину выбрать?»;
- «сколько нужно источников?» / «когда достаточно?»;
- любой вход в поиск, где не зафиксированы цель и критерий остановки.

**НЕ используется для:** самого поиска, скачивания, извлечения текста, синтеза/верификации (это уже другие инструменты/скиллы).

## Запрещено (scope)

- **НЕ запускать поиск** (никаких каналов: корпус, arxiv, openalex, searxng, downloader, book_finder).
- **НЕ скачивать файлы** и не извлекать текст.
- **НЕ выполнять запросы к каналам** — даже «пробные».
- Итог skill — только **verdict** (оценка), управление передаётся поисковому агенту.

## Шаг 1. Оцени задачу — 4 вопроса контракта глубины

Отвечай на каждый вопрос по контракту `shared/search-depth-contract.md` (TD-170):

1. **Что ищем?** — конкретный факт / полный текст / TOC / DOI / ISBN (поле `need`).
2. **Зачем?** — для какого claim/BRICK (`claim_id`), какая точность нужна для ЭТОГО claim.
3. **Сколько нужно?** — 1 источник / 3-5 / исчерпывающе.
4. **Когда достаточно?** — критерий остановки (напр. «TOC хватает для B1», «нужен полный текст — иначе not_found»).

## Шаг 2. Оцени контекст — что уже есть вокруг

1. **Что уже нашли в этой сессии?** — не перепроверять; сверить артефакты (`sources_<id>.json`, `prov.json`, заметки).
2. **Что лежит рядом в корпусе/каталогах?** — соседние файлы той же категории, смежные разделы ГОСТ/справочников (lib-bkm: `/load/104` Материаловедение, `/load/25` ГОСТы, `/load/135` Диссертации), перекрёстные ссылки в TOC/литературе.
3. **Какие каналы доступны?** — список в разделе «Каналы поиска» контракта глубины (corpus → arxiv/openalex → searxng/webfetch → downloader resolve → book_finder → sci_bot + mirror-обходы).

## Шаг 3. Выбери глубину (поверхностный / средний / глубокий)

| Глубина | Каналы | Когда |
|---|---|---|
| **поверхностный** | 1 канал (локальный корпус ИЛИ первый релевантный) | факт из памяти/корпуса, быстрый ответ |
| **средний** | 3-5 (corpus → arxiv/openalex → searxng/webfetch → downloader resolve) | стандартная верификация claim |
| **глубокий** | все + mirror-обходы (libgen/annas/lib-bkm, DNS-bypass, captcha-маркер) | полный текст/книга/редкий источник |

Правило: **не углубляться, когда для текущего claim достаточно TOC/поверхностного.**

## Шаг 4. Верни verdict и передай управление

Верни verdict (JSON-артефакт/запись в контракт задачи):

```json
{
  "goal": "<что ищем>",
  "need": "fact|fulltext|toc|doi|isbn",
  "depth": "поверхностный|средний|глубокий",
  "stop_criterion": "<когда достаточно>",
  "context_survey": "<что уже нашли / что вокруг / какие каналы>"
}
```

Затем **передай управление поисковому агенту** (`unified_search`) с выбранной глубиной и критерием остановки. Сам skill поиск НЕ выполняет.

## Проверка (чеклист перед verdict)

- [ ] Ответил на все 4 вопроса (что/зачем/сколько/когда достаточно)?
- [ ] Учел контекст: что уже нашли, что лежит рядом, какие каналы доступны?
- [ ] Глубина выбрана по таблице и НЕ избыточна для текущего claim?
- [ ] Критерий остановки явный (можно проверить «достаточно / not_found»)?
- [ ] Поиск НЕ запускался, файлы НЕ скачивались, каналы НЕ опрашивались?
