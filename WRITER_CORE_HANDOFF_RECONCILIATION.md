## Classification rules

- `IMPLEMENTED`: current runtime code performs the material behavior and has a concrete validation path.
- `PARTIAL`: a useful runtime slice exists, but the handoff contract is broader or lacks a complete test/gate.
- `SPEC_ONLY`: only design, schema, fixture, registry, or reference skeleton evidence exists.
- `LEGACY`: retained only as historical/migration input, not current authority.
- `DUPLICATE`: a second implementation/specification overlaps a current authority and should not become another source of truth.
- Decisions mean: `INTEGRATE` a bounded contract/adapter is an M4 candidate; `KEEP_SPEC` retain as reference or test oracle; `DEFER` valuable but not a small safe integration now; `REJECT` do not bring into the writer runtime.

## Current dependency and routing facts

1. **One-way review dependency.** `scripts/writer-core/writer_core/review.py:607-618` imports and calls `scripts/writer/citation_trace.py` through `_run_citation_trace`; citation trace does not import `writer_core.review`. Thus the current direction is **hybrid review → citation_trace**, not a bidirectional merge. Preserve this boundary: traceability is an input to the L3 verdict, while citation trace remains independently runnable.
2. **Current `writing-prose` router stages.** `config/stage_capsules_authority.json:23-30` is the current machine-readable authority: `claim-load → draft → semantic-validation → repair`. `claim-load` requires `writer.claims.read`; `draft` requires `writer.draft` and forbids `web.discovery`/`code.edit`; `semantic-validation` requires `writer.semantic_validate` and forbids `web.discovery`; `repair` requires `writer.draft`, forbids `web.discovery`, and is terminal. This route does not contain a separate named researcher verification or release/export stage.
3. **Provider boundary.** `agent.writer` owns claim loading and drafting. `local.writer_core` advertises only semantic validation and wins that capability when its `WRITER_PYTHON` command probe passes; a failed interpreter probe degrades it without falsely claiming availability.
4. **Agent/skill evidence boundary.** `agents/writing-orchestrator.md`, `agents/article-writer.md`, and the writer skills direct operators to current scripts, but instructions alone cannot upgrade a matrix row to `IMPLEMENTED`. Script behavior and tests remain the acceptance evidence.
5. **Clean dependency boundary.** Current runtime loads its six consumed registries from `scripts/writer-core/linguistic_assets/` and its minimal RTT/digest models from `scripts/writer-core/writer_core/`. Recursive Python-source checks under `scripts/writer-core/` find no handoff/archive path, former temporary-runtime namespace, or external drive-literal runtime path. The handoff can therefore be absent from `sys.path` and from the runtime filesystem.

## Prioritized M4 candidates

Only the following small, mutually beneficial integrations are recommended. They preserve the current runtime and turn selected handoff material into tested contracts rather than importing the architecture wholesale.

### M4-1 — Freeze a minimal Researcher→Writer contract adapter (P0)

- **Contract:** define one canonical versioned mapping for researcher/DOM claim fields (`claim_id`, proposition/text, source/evidence refs, verdict, confidence, numeric comparison, scope/modality/causal constraints). Adapter output must validate without silently inventing evidence or upgrading eligibility. Keep full handoff semantic types out of scope.
- **Test:** positive round-trip fixture plus negative cases for missing claim ID, unknown verdict, evidence-less factual eligibility, and lossy qualifier/scope mapping; assert current `WriterContract`/DOM behavior remains compatible.
- **Sunset:** retire the adapter when writer and researcher import the same versioned model package and compatibility tests pass for two consecutive releases; otherwise review on any DOM or researcher policy version change.
- **Benefit:** removes ambiguity between `ResearchBundleLA`, Writer DOM, and `verify_claims` while helping both writer and researcher without changing prose generation.

### M4-2 — Make RTT fixtures executable and remove archive-path authority (P0, completed 2026-09-10)

- **Contract:** runtime-owned RTT enums/result model and comparator must emit stable reason codes for the four handoff round-trip examples and selected linguistic golden traps; no absolute path to an external/handoff skeleton.
- **Test:** parameterized tests for `pass_safe_paraphrase`, `fail_scope_shift`, `fail_numeric_drift`, `fail_causality_upgrade`, plus bounded-repair/no-progress behavior. Validate emitted JSON against the selected RTT result shape.
- **Sunset:** delete the compatibility fixture layer after the canonical runtime RTT schema reaches a declared v1 and all callers use it; reassess whenever reason-code enum changes.
- **Benefit:** hardens an already-used runtime path and eliminates a fragile archive dependency without adopting speculative compiler layers.

### M4-3 — Add an explicit verify-claims precondition to semantic validation (P1)

- **Contract:** before traceability/review can produce a releasable verdict for sourced factual claims, a deterministic `verify_claims` report must be present; its exit/verdict and DOM updates are inputs, not silently inferred success. Preserve the independent `citation_trace` command and the one-way review dependency.
- **Test:** route/process fixture proving `verify_claims FAIL` blocks citation/release handoff, `verify_claims PASS` proceeds to citation trace, and citation failure still blocks independently. Reuse `tests/test_verify_claims.py` and `tests/test_citation_trace.py` fixtures.
- **Sunset:** fold this precondition into a future aggregate release gate once that gate has equivalent negative tests; review if `writing-prose` stage names change.
- **Benefit:** closes the documented WS-19 gap and prevents traceability PASS from being mistaken for evidence-validity PASS.

### M4-4 — Vendor only the consumed linguistic contract subset (P1, completed 2026-09-10)

- **Contract:** identify and version the six registries actually loaded by `registry_loader.py` and the minimal `LinguisticDigest`/RTT types actually imported; reject unknown/malformed entries fail-closed. Do not copy all templates, schemas, OSINT assets, caches, or generated output.
- **Test:** load each consumed registry from the canonical runtime location, validate required keys and duplicate IDs/forms, run golden modality/causality/connective traps, and prove runtime works when `scripts/writer_core_handoff` is absent from `sys.path`.
- **Sunset:** review the runtime-owned copy/adapter on registry schema version change. A future M4-4 sunset may replace it only with another tested runtime package; it cannot make `scripts/writer_core_handoff/` a runtime dependency or authority.
- **Benefit:** keeps the useful linguistic data while restoring a clean spec/runtime boundary.
