> Назначение: ДОПОЛНЕНИЕ к контрактам ревьюера и аудитора. Оркестратор вставляет этот файл в промпт ревьюеру и аудитору после КАЖДОГО завершённого блока. Каждый найденный техдолг фиксируется ТЕМ, КТО НАШЁЛ — сразу, с комментарием, в `docs/PROBLEMS_REGISTER.md` и в git (коммит делает деплоер).

---

## 1. НАЗНАЧЕНИЕ

Каждый найденный техдолг фиксируется **ТЕМ, КТО НАШЁЛ** (ревьюером или аудитором) — сразу, с комментарием, в `docs/PROBLEMS_REGISTER.md` + в git.

Проблемы, найденные при ревью/аудите, — это материал для аналитиков: из них выводятся подзадачи и решения пользователя. Хаотичная регистрация (деплоер вручную, задним числом) теряет контекст «почему» и «при каких условиях закрывается». Обязанность фиксации — на нашедшем.

## 2. КОГДА ФИКСИРОВАТЬ

- Junction отложен / решение отложено (`REQUIRES_USER_DECISION`) → **TD-HIGH**
- Ложный отчёт воркера (DoD FAIL, но PASS заявлен) → **TD** + замечание в ревью
- Дефект спецификации (путь неверный, файл не там) → **TD-MEDIUM**
- Отсутствие артефакта/процесса (нет бэкапа, нет snapshot) → **TD-MEDIUM**
- `.gitignore` без runtime-паттернов → **TD-LOW/MEDIUM**
- Любой риск для live/прода → **TD-HIGH** с пометкой `(live)`

## 3. ФОРМАТ ЗАПИСИ (в PROBLEMS_REGISTER)

Секция «ТЕХДОЛГИ РАЗРАБОТКИ», одна строка на TD:

| TD-ID | Severity | Что | Комментарий (почему, условия закрытия) | Блок | Статус |
|-------|----------|-----|-----------------------------------------|------|--------|
| `TD-DEV-N` | HIGH/MEDIUM/LOW | <кратко что> | <почему это техдолг + условия закрытия> | <B*/W*/M*> | OPEN |

## 4. ПРОЦЕДУРА (для ревьюера и аудитора)

1. Нашёл проблему → присвой TD-ID (следующий свободный `TD-DEV-N`).
2. Запиши в `docs/PROBLEMS_REGISTER.md` (секция «ТЕХДОЛГИ РАЗРАБОТКИ») с полным комментарием:
   - что за техдолг, почему это техдолг (не баг / не фича);
   - условия закрытия (какая подзадача / решение пользователя);
   - блок (`B*` / `W*` / `M*`).
3. Если файла `PROBLEMS_REGISTER.md` нет — создай.
4. В СВОЁМ ОТЧЁТЕ (вердикт) перечисли зарегистрированные TD-ID (чтобы деплоер их закоммитил).
5. Деплоер коммитит `PROBLEMS_REGISTER.md` + вердикт-JSON (шаг 3.5 контракта 04).

## 5. ПРАВИЛА

- Не дублировать существующие TD-ID (проверить перед записью).
- Комментарий обязателен (что/почему/условия закрытия) — это материал для аналитиков.
- Severity: **HIGH** (блокирует / риск live), **MEDIUM** (процесс), **LOW** (косметика).
- Каждый TD = строка в `PROBLEMS_REGISTER.md` + в вердикте ревьюера/аудитора.
