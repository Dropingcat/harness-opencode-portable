# 14_AUDITOR_MODES.md — Двурежимный контракт аудитора (A: in-cycle / B: standalone)
**Дата:** 2026-10-07 · **Статус:** АКТИВЕН · **Версия:** 1.0

## 1. ПРОБЛЕМА (реальный кейс)
Диспетчер дал аудитору трибунальный контракт (режим A) на внешний аудит черновика (ГОСТ EN 13132 + xlsx). Аудитор застрял: «нет вердикта ревьюера → INVALID_INPUT?». Провал: контекст потрачен на метания, внешний аудит не выполнен.

## 2. ДВА РЕЖИМА (обязательно)

### РЕЖИМ A — IN-CYCLE (внутри фабричного цикла)
- **Когда:** аудит звена в полном конвейере worker → reviewer → auditor → analyst → researcher → deployer.
- **Вход:** вердикт ревьюера (текстом), worker JSON + reviewer JSON, метрики процесса (iteration_count, iteration_limit), спека блока, PROBLEMS_REGISTER, контракты 05/07/09/10.
- **Правило:** если в контракте передан «путь к файлу кода воркера» без пары ревьюер/воркер — это нарушение разделения ролей → **INVALID_INPUT**.
- **Выход:** вердикт APPROVE/REQUEST_CHANGES/REJECT + TD + секция 0 (07).

### РЕЖИМ B — STANDALONE (внешний аудит черновика/документации/артефактов)
- **Когда:** аудит объекта ВНЕ полного цикла — черновик, шаблон, документация, книги Excel, НД-сопоставление, новая область без фабричных артефактов.
- **Вход:** ОБЪЕКТ аудита (пути к файлам/папкам ДОПУСТИМЫ — это аудируемые артефакты, НЕ «код воркера»), КРИТЕРИИ (НД: ГОСТ/GUM/JCGM, контракты CODERS, требования задачи), PROBLEMS_REGISTER (если есть), контекст.
- **Правило:** НЕ ждать вердикта ревьюера — его нет. Выполнять аудит ПО СУЩЕСТВУ: въедливо (07), проверять факты командами (verify), фиксировать находки (05/09), выносить вердикт по готовности/соответствию.
- **Выход:** вердикт (APPROVE/REQUEST_CHANGES/REJECT) + находки по уровням 09 + TD (05) + секция 0 (07).

## 3. ДИСПЕТЧЕР ОБЯЗАН УКАЗАТЬ РЕЖИМ
- При каждом запуске аудитора в промпте ПЕРВОЙ строкой: `РЕЖИМ: A` или `РЕЖИМ: B`.
- Если режим не указан — аудитор запрашивает уточнение (НЕ мечется): «Режим не указан. Запуск in-cycle (A) или standalone (B)?» — и ждёт ответа ИЛИ выбирает B, если явно нет пары ревьюер/воркер (зафиксировав выбор).
- Диспетчер не должен давать сырой стандартный контракт: шаблон с обязательным полем режима.

## 4. СРАВНИТЕЛЬНАЯ ТАБЛИЦА
| Измерение | A (in-cycle) | B (standalone) |
|---|---|---|
| Место | полный конвейер | вне цикла, объект-аудит |
| Вход | вердикт ревьюера + worker JSON + метрики | объект + критерии + НД |
| Пути к файлам | запрещены (код воркера → INVALID_INPUT) | ДОПУСТИМЫ (это аудируемые артефакты) |
| Чего НЕ ждать | — | вердикта ревьюера (его нет) |
| Фокус | процесс + интеграция | существо объекта + соответствие критериям |
| Выход | вердикт + TD + секция 0 | вердикт + находки 09 + TD + секция 0 |

## 5. СВЯЗЬ С ДРУГИМИ КОНТРАКТАМИ
05 (TD), 06 (порядок), 07 (въедливость), 09 (эскап-хэтч), 10 (входы), 13 (цикл: диспетчер выбирает режим)
