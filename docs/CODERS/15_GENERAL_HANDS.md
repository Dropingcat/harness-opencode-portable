# 15_GENERAL_HANDS.md — General = руки оркестратора (универсальный шаблон контракта)
**Дата:** 2026-10-07 · **Статус:** АКТИВЕН · **Версия:** 1.0

## 1. АРХИТЕКТУРНЫЙ ПРИНЦИП
- Оркестратор (code/writing/research-orchestrator, любой диспетчер) = МОЗГ: думает, планирует, держит глобальный базлайн (трекер, ANALYST_REPORTS, PROBLEMS_REGISTER, ORCHESTRATOR_NOTES), капсулу контекста, пишет контракты, принимает решения.
- Агент general = РУКИ: выполняет любую работу (правка файлов, команды, исследование, git, артефакты) по контракту оркестратора.
- Правило: оркестратор НЕ делает руками то, что может делегировать general (экономия контекста мозга на мышление).
- Исключения: специализированные звенья (customer-worker/code-reviewer/code-auditor/synthesizer/source-fetcher/fact-checker/деплоер) остаются по своим контрактам (11); general — универсальный исполнитель для задач вне специализации и для «ручных» операций оркестратора.

## 2. УНИВЕРСАЛЬНЫЙ ШАБЛОН КОНТРАКТА ДЛЯ GENERAL (с переменными)

```text
Ты — РУКИ ОРКЕСТРАТОРА (general-исполнитель). Выполни задачу по контракту. Не думай о решениях — всё предрешено.

## ЗАДАЧА ({{TASK}})
{{Краткое описание: что сделать, зачем}}

## КОНТРАКТ ВХОДА
### Объект работы:
- Файлы/пути: {{PATHS}} (что читать/править/создавать)
- Текущее состояние: {{CURRENT_STATE}} (что есть сейчас)

### Требования:
- {{REQUIREMENTS}} (что именно сделать, критерии)

## ШАГИ ({{STEPS}})
1. {{STEP_1}}: команда/действие
2. {{STEP_2}}: ...

## КОНТРАКТ ВЫХОДА
### Секция 1: {{RESULT}} (что сделано, пути)
### Секция 2: Проверки (таблица: проверка → команда → ожидание → факт → PASS/FAIL)
### Секция 3: Техдолги (перечисли, НЕ регистрируй в реестр — это сделает звено/оркестратор)
### Секция 4: Находки по 09 (уровень 1/2/3, если есть)

## ПРАВИЛА
- Выполняй реально (запускай команды, читай файлы). Не выдумывай.
- Артефакт-путь: {{ARTIFACT_PATH}} (по шаблону 10 §9 / 12).
- НЕ коммить (деплоер по контракту 04 или оркестратор).
- НЕ выходи за scope задачи ({{SCOPE}}).
```

## 3. ПЕРЕМЕННЫЕ ТАБЛИЦЫ
| Переменная | Назначение | Пример |
|---|---|---|
| {{TASK}} | суть задачи | «Создай CONFIG_MERGE.md» |
| {{PATHS}} | файлы/пути | E:\opencode_harness_portable\config\CONFIG_MERGE.md |
| {{CURRENT_STATE}} | что есть | «данные EXP-1b собраны» |
| {{REQUIREMENTS}} | требования/критерии | «запиши результаты A-D» |
| {{STEPS}} | шаги | «1. Прочитай... 2. Запиши...» |
| {{RESULT}} | формат выхода | «путь, размер, первые строки» |
| {{ARTIFACT_PATH}} | куда писать артефакт | ${HARNESS_ROOT}/analyst_X.json |
| {{SCOPE}} | границы | «не трогай конфиги» |

## 4. КОГДА ДЕЛЕГИРОВАТЬ GENERAL (для оркестратора)
- Правка файлов (документация, контракты, README).
- Запуск команд/скриптов, проверки.
- Исследование/чтение (если не требует специализации).
- Создание артефактов/отчётов по шаблону.
- Git-операции (когда не деплой).
- Подготовка материала для специализированных звеньев.
НЕ делегировать: вердикты ревьюера/аудитора (спец-агенты), написание воркер-кода (coder-worker), деплой (04).

## 5. ОРКЕСТРАТОР = КАПСУЛА И БАЗЛАЙН
- Оркестратор держит капсулу: контекст сессии, решения, состояние проектов (12), глобальный базлайн (ANALYST_REPORTS + PROBLEMS_REGISTER + ORCHESTRATOR_NOTES + трекер).
- При делегировании general: передавать только нужный минимум контекста (не всю капсулу), остальное — по путям (файлы базлайна).
- После возврата general: оркестратор обновляет капсулу (что изменилось), фиксирует TD/находки.
