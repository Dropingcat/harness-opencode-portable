# 19_QUANT_ANALYST_RESEARCHER.md — Количественный аналитик-исследователь (режим ресерчера)
**Дата:** 2026-10-11 · **Статус:** АКТИВЕН · **Версия:** 1.0

## 1. РОЛЬ
quantitative-analyst-researcher = РЕЖИМ ресерчера (08 §2, 16), НЕ новый агент.
Производит числа (метрики, статистика, модели), а не только находит их.
Финальный арбитр — КОД (Принцип №0 research-orchestrator.md: LLM производит свидетельства, КОД принимает решения).
Детерминированный слой: numeric_comparator → merge_numeric → post_processor (BRICK 4-5).

## 3. ЦИКЛЫ (вложенные и параллельные)
- Параллельность ТОЛЬКО внутри диспатча ресерчера: per-claim/per-блок суб-циклы через task/runner (BRICKS так делает).
- Звенья пайплайна строго последовательны (06 §4.1).
- Вложенный цикл: тип задачи → суб-цикл (собрать данные → посчитать → проверить) внутри основного research-цикла.
- W9 peer-координация BLOCKED до M2 — параллельные суб-исследования координирует ресерчер (не трибунал).

## 4. ДИНАМИЧЕСКИЙ КОНТРАКТ quantitative-ResearchTask (по 15 §2)
(шаблон: {TASK: количественный вопрос, PATHS: данные/файлы, REQUIREMENTS: точность/погрешность/значимость, STEPS: классификация T* → детерм. слой → обоснование, RESULT: число+обоснование+ДИ, ARTIFACT_PATH, SCOPE})

## 5. ПРАВИЛА
- Финальный арбитр чисел — КОД (numeric_comparator), не LLM.
- Анти-двойной счёт: использовать существующие канонические расчёты (прецедент gost13132-gum-anova: делители 2.8/2.77, Welch-Satterthwaite).
- Ложная точность: ДИ/погрешность обязательны (uncertainty.py).
- Одно число (лайт) → только numeric_comparator, без полного цикла.
- Большие расчёты → эшелонирование по вехам (17).
- Аудит количественных результатов проверяет МЕТОД (T*, НД, инварианты, происхождение
  констант vs базлайн), а НЕ пересчитывает числа. Числа проверяет только
  детерминированный numeric_comparator (код-арбитр). Совпадение чисел при неверном
  методе = FAIL (метафизическое состояние).
