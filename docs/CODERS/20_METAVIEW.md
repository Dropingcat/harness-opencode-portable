# 20_METAVIEW.md — Мета-взгляд агента (анти-просачивание контекста)
**Дата:** 2026-10-12 · **Статус:** АКТИВЕН · **Версия:** 1.0

## 1. ГИПЕР-БАГ (что решаем)
Контекст тестовой задачи просачивается в контекст разработки harness: агент забывает,
что он ТЕСТИРУЕТ фабрику, и начинает параллельно ВЫПОЛНЯТЬ задачу, запущенную тестером
(прецедент: E2E-тест gost13132 — агент вошёл в ГОСТ-методологию вместо проверки цикла).
Причина: нет якоря базовой задачи, нет взгляда со стороны, нет сопоставления действий
с базлайном ЗАДАЧИ (harness) вместо базлайна ТЕСТА.

## 2. ПРИНЦИП
Агент, выполняющий E2E-тест, работает в ДВУХ контекстах:
- БАЗОВАЯ ЗАДАЧА (harness-разработка): разрабатываем блоки, проверяем их.
- ТЕСТОВАЯ ЗАДАЧА (gost13132): материал для теста.
Агент обязан ПОМНИТЬ базовую задачу и исследовать цепочку действий теста ЛОГИЧНО
в контексте ЗАДАЧИ, а не ТЕСТА. «Ага, E2E делает 1,2,3 — мы разработали эти блоки —
как он их использует? правильно ли? работают ли?»

## 3. МЕХАНИЗМЫ

### 3.1 Якорь базовой задачи (base-task capsule) — ДИНАМИЧЕСКИЙ
- Капсула НЕ хардкодится («я тестирую фабрику» — только для разработки фабрики).
- Капсула ГЕНЕРИРУЕТСЯ из базлайна ТЕКУЩЕЙ задачи перед E2E-диспатчем:
  - источник 1: трекер (todowrite/tracker) — текущая задача, её стадия, блоки
  - источник 2: PROBLEMS_REGISTER (tech_debt.md проекта) — какие техдолги тестируются
  - источник 3: контракты (docs/CODERS/*.md) — какие механизмы под тестом
  - источник 4: PROJECT config (12) — артефакты, переменные
- Генератор: роутер-наблюдатель (W5 observer-режим) собирает капсулу
  `projects/<PID>/contracts/base-task-capsule.md` ПЕРЕД диспатчем тестировщика
  и ПЕРЕГЕНЕРИРУЕТ при изменении базлайна (новая стадия, новый TD).
- Содержимое капсулы (шаблон):
  {base_task: "<что разрабатывается СЕЙЧАС>", test_material: "<что тестируется>",
   blocks_under_test: [<блоки из трекера>], td_under_test: [<TD из реестра>],
   invariants: [<что должно работать>], forbidden: [<что НЕ делать>]}
- Цикл: роутер сверяет капсулу с фактическими действиями агента (детекторы D1-D9)
  и добрасывает контекст при дрейфе — капсула «живая», не висит портами наружу.
- Правило: агент ПЕРЕЧИТЫВАЕТ капсулу при каждом self-check (30 шагов) и
  при добрасывании контекста роутером.
- Файл/путь/цитирование (по 12/17, 06 §4.5) — как раньше: `projects/<PID>/contracts/base-task-capsule.md`
  цитируется в промпты ВСЕХ звеньев как спека; обязательная секция в контракте
  тестировщика: «Я ТЕСТИРУЮ ФАБРИКУ. Тестовая задача — материал. Не выполняй её —
  проверяй, как фабрика её обрабатывает» (текст секции генерируется из капсулы).

### 3.2 Взгляд со стороны (reflective loop)
- Self-check каждые N=30 шагов: «какая цепочка моих действий? логична ли в контексте базлайна ЗАДАЧИ?»
- Обязательный артефакт: `observer_<ID>.json`:
  {chain_of_actions: [...], leakage_detectors_fired: [...], verdict: ON_BASE_TASK|DRIFTING, base_task_anchor: "разработка harness"}
- Сопоставление реестра блоков (function_index.json + git log) с тем, что тест использует.

### 3.3 Роутер-наблюдатель (observer router)
- РЕЖИМ/команда `observer` существующего W5: `scripts/router/observer_router.py`.
- Подключается по триггерам: E2E-тест, длинные цепочки (≥120 шагов), любой детектор D1-D9.
- Добрасывает контекст в сессию суб-агента при уплывании: «СТОП, ты тестируешь. Вернись к базовой задаче».
- НЕ дублирует W9 (peer) и M3 (трибунал): просачивание — не спор звеньев, а потеря ориентации.

### 3.4 Активная сессия сна
- W13 сон: снять --simulate/--no-git (TD-DEV-28), LogonType=S4U (TD-DEV-27).
- Новая секция `reflection` в отчёте сна: built_today vs used_by_tests, drift_events, lessons → L2/W10.

### 3.5 Детекторы просачивания (D1-D9)
| ID | Сигнал | Команда проверки |
|----|--------|------------------|
| D1 | правит файлы тестовой задачи (пути C:\Users\...\каллибровка) | grep контракта по путям теста |
| D2 | пересчитывает ГОСТ-методику вместо проверки цикла | grep действий по методологии теста |
| D3 | долго (>30 шагов) без self-check | счётчик шагов |
| D4 | создаёт артефакты вне контракта (не *.json шаблона) | ls новых файлов |
| D5 | в отчёте нет секции «Я тестирую фабрику» | grep секции |
| D6 | пишет в файлы теста (не read-only) | git status теста |
| D7 | контекст уплыл в детали задачи (ГОСТ-разделы) | анализ цепочки |
| D8 | нет observer_<ID>.json при длинной цепочке | Test-Path |
| D9 | вердикт звена не связан с базовой задачей | аудит метафизических состояний |
