# TD-184 — блокер штатного вложенного диспатча фабрики

**Статус:** OPEN / BLOCKED_NESTED_DISPATCH. **Приоритет:** critical. **Владелец:** code-orchestrator. **Sunset:** до сертификации штатного вложенного диспатча. Источник статуса — канонический config/tech_debt.json, этот документ описывает доказательства и проверку закрытия.

**Явное исключение для A2:** после предупреждения об открытом блокере пользователь выбрал «A2 через отдельные CLI-сессии». Разрешены реальные специализированные профили в самостоятельных сессиях с проверкой agent ID; parentID=null честно фиксируется. Это разрешение на обходной режим для A2, не закрытие TD-184 и не доказательство работы nested-фабрики. Остальные критерии закрытия ниже сохраняются.

## Подтверждённый симптом

OpenCode Desktop/CLI 2.0.29: coder-worker-runner завершил сессию сообщением, что не может вызвать coder-worker из-за отсутствующего task-инструмента; worker-артефакт не появился. Exit 0 обёртки не является успехом диспатча. Корневая причина — имя/каталог инструментов, регистрация целей, права или другой разрыв — ещё не установлена; сообщение модели не заменяет проверку runtime.

При A1 специализированные coder-worker/code-reviewer/code-tester/code-auditor были фактически выбраны в отдельных CLI-сессиях. Сервер подтвердил agent ID, но parentID был null. Это отдельные сессии, не штатные вложенные субагенты текущего оркестратора.

Аналитик, LIGHT-ресерчер и деплоер были настоящими general-дочерними агентами с parentID текущей беседы. Ролевое название задачи не меняет их agent ID. Допустимость general по контракту 15 не доказывает работу специализированного диспатча.

## Влияние и зависимости

- A2 не запускать до разрешения этого блокера либо отдельного явного решения пользователя о другом режиме исполнения.
- Не считать отдельный CLI-запуск или переименование general исправлением вложенной фабрики.
- Принятый результат A1 не отменяется: его фактические роли, независимые проверки, ограничения и release-доказательства сохранены. Не приписывать ему доказательство штатной вложенной цепочки.
- Связанные, но не тождественные долги: TD-117 (исторический CLI fallback), TD-121/TD-099 (кросс-оркестрация), TD-174 (наблюдение), TD-RESTORE-01 (полная V2-автономность). Исторически закрытые долги не переоткрываются массово.

## Критерии закрытия

1. В живой новой сессии 2.0.29 определены доступный task или поддерживаемый native-эквивалент, разрешённые цели и реальные права. Предусловие проверяет код; отсутствие возможности выдаёт BLOCK до работы исполнителя.
2. Из оркестратора/primary-обёртки создаются настоящие специализированные дочерние coder-worker, code-reviewer, code-tester, code-auditor с ожидаемыми серверными agent ID и parentID, относящимся к запустившей цепочке. Поле title или самозаявление агента недостаточны.
3. Входной контракт, артефакт результата, agent/session/parent IDs, разрешения и исход связаны корреляцией. Wrapper только транспортирует, не пишет код за воркера и не подменяет его general.
4. Ошибки регистрации/инструментов/прав, отсутствующий или неверный результат, таймаут и отмена дают структурированный отказ; CLI exit 0 без child/artifact не принимается. Отмена не оставляет неучтённых дочерних работ.
5. Пройдены ограниченный E2E, холодный запуск и две параллельные цепочки без смешения родителей/артефактов, с независимой проверкой по API. Нельзя вручную дорисовать parentID.
6. Документы CODERS и runner-профили согласованы с проверенным V2-механизмом. Отчёт и UI-наблюдаемость различают general, специализированного ребёнка и отдельную CLI-сессию. При несовместимости после обновления блокировка сохраняется.
7. Контент-guard, бюджеты, scope и режим A процессного аудитора не ослаблены ради прохождения теста. Для аналитика/деплоера general допустим только как явно объявленный выбор по контракту, не имитация другого профиля.
