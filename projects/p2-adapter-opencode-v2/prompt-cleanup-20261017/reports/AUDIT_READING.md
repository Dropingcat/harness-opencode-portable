В аудите предлагается перенести управление выполнением из инструкций LLM в проверяемый
кодовый цикл `Plan → Dispatch → Validate → Replan`. Это обоснованное направление:
наличие маршрута, роли, схемы или unit-теста не доказывает сквозное исполнение на хосте.
Но документ — архитектурное предложение с отдельными наблюдениями по публичному репозиторию,
а не актуальный приёмочный отчёт локальной сборки. Его статусы нельзя переносить в трекер автоматически.

## Что стоит принять из рекомендаций

**Развести Router и Planner** (§3). Router выбирает контур, средства и ограничения.
Planner предлагает зависимости и изменения плана. Код проверяет допустимость переходов,
сохраняет состояние и не позволяет исполнителю ослабить критерии приёмки.

**Перепланировать локально** (§5). Ошибка отдельной ветви должна инвалидировать её зависимые
результаты, а не перезапускать весь процесс и не переписывать подтверждённые части.
Для этого каждому узлу нужны идентификатор, входы, зависимости, разрешения, бюджет,
проверка результата и ссылка на evidence.

**Разделить память по уровню подтверждения** (§4). Неудачная гипотеза полезна как эпизод,
но не должна попадать в подтверждённые уроки. Admission в долговременную память должен
хранить происхождение, scope, подтверждение и условия пересмотра. Это рекомендация;
полнота текущей memory-реализации здесь не проверялась.

## Чего аудит не доказывает

- Сопоставимость OpenCode, Claude Code и Codex как взаимозаменяемых runtime-адаптеров:
  это целевая архитектура, требующая отдельной матрицы контрактов и проверок.
- Лучшее качество или меньшую полную стоимость конкретной GLM/DeepSeek-маршрутизации:
  измерений нет. Примеры моделей не разрешают переключать провайдера текущей сессии.
- Готовность активного плагина, runtime isolation, отмены или cleanup. Нужны
  наблюдаемые целевые сценарии; компонентный PASS не подменяет host evidence.
- Актуальность всех приведённых TD-ID, статусов и сравнений с Claude Code. В экспортированном
  тексте есть citation-заглушки `GitHub +N`; точные первоисточники части тезисов не восстановлены.

## Предлагаемый порядок продолжения — не выполнялся

1. Сверить `implemented / component-tested / host-observed` по одному минимальному
   сквозному сценарию, с явными session/context/model binding и ownership ресурсов.
2. Связать существующие contract validation, state reducer и specialized dispatch
   в один воспроизводимый цикл. Не начинать с шести новых Deep-контуров.
3. Добавить типизированный отказ, локальную ревизию плана, инвалидацию зависимого evidence
   и ограничение повторов. Независимые gates и пользовательские полномочия остаются отдельными.
4. Только после доказанного цикла расширять память, выбор моделей и общий scheduler.
