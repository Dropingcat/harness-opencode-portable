# C-Probe: геймификация оркестратора — обзор GitHub-идей

Дата: 2026-09-06. Обзор архитектурных идей для «игры в игру» фабрики кода.
Цель — не «играть с токенами», а: (1) усилить желание делегировать, (2) занять агента в простое
полезным, (3) дать оркестратору видимую цель с обратной связью.

## Что сняли с GitHub (топ-находки)

### 1. prompt-warrior (23★) — «логи = персонаж»
- Читает локальные сессионные логи харнесса (**OpenCode поддерживается**:
  `$OPENCODE_DATA_DIR/message/{sessionID}/msg_*.json`, дефолт `~/.local/share/opencode`).
- 100% stdlib Python, **ноль зависимостей**, read-only, никакой сети.
- 74 ачивки с rarity + замороженными формулами (`references/scale.md`) — все детерминированы.
- Модель пишет только «хронику» (биографию/сильные-слабые), а числа и HTML — код.
- **Переносимая идея:** «хардкод формул в код, LLM только интерпретация».

### 2. WorldLines / LudicDynamics (72★) — «мир из агентов»
- File-backed, **event-sourced, git-diffable**: мир = машина состояний, каждый turn = append-only Event.
- Оркестрация: `world-agent` (владеет каноном: state/routing/narration/archive) → `soul-agents`
  (per-персона: persona/memory/secrets/goals). Это **ровно** структура «оркестратор → воркеры».
- Пайплайн **Plan–Diff–Validate–Apply** с schema-validated JSON дельтами — маппится на наш
  `factory_ctl submit` (контракт → валидатор → state machine).
- Проприетарное ядро (`neonrp`) — модель-агностик, локально, DeepSeek/Ollama ок.
- **Переносимая идея:** превратить наш `delegation_ledger`/`.kanban.db` в единый event-log с read-моделью.

### 3. token-tamers (7★) — «тамагочи из токенов»
- Idle-пет, **read-only**, никогда не тратит токены, полный оффлайн.
- Адаптеры → **один нормализованный event-stream**; движок не знает, какой агент кормит.
- **Прогресс нормализуется к собственному baseline** — маленькая модель = так же сильный пет.
- Модели влияют на «вид/породу», НЕ на силу; смесь агентов = гибриды.
- Битвы **детерминированы** по DNA-коду (same-input → same-outcome).
- **Переносимая идея:** baseline-normalization + конкурентный «поединок по статисткам» между агентами.

### 4. cco-arcade (egorfedorov, 2★) — «город из работы»
- **Производное состояние никогда не хранится**: Godzilla-damage вычисляется на лету из дат.
- Пинги «агент закончил длинный turn / ждёт permission» — **smart-уведомления по реальным событиям**.
- **Переносимая идея:** «домен состояния = функция от фактов, не отдельная БД» + тайминги.

### 5. agent-idle-games / unkownpr/ai-agent-idle-game (2★) — «в игре играет агент»
- Сама идея «агент кликает в idle-игре» — интересна как *отвлечение*, но:
  токены при этом жжёт агент, ценность низкая. Для оркестратора предпочитаем **детерминированную
  агенду** (наш idle_tasks.py), а не LLM-«релакс».

## Рекомендация

- **A (сделано)** — character_sheet: источники фактов уже читаются read-only; расширение —
  opencode-сессии (metrics поведения), но это опциональный слоёк, чтобы не жёчь токены.
- **B (сделано)** — idle_tasks.py: детерминированная агенда; ничего не пишет.
- **C (probing)** — не строить сразу «живой мир». Взять по одному переносимому приёму:
  1) event-log / read-model над имеющимся (леджер+канбан) — дешёвый и даёт «доску»;
  2) baseline-normalization в чаршите;
  3) детерминированный «поединок» агентов как мотиватор (без сети).
  WorldLines-масштаб (soul-agents с памятью и целями) — не таргет: токены на агентов-«душ»
  сожгут бюджет ради гейминга.

## Статус внедрения (2026-09-06)
- **A — сделано:** `character_sheet.py` (XP/level/ачивки из канбана+памяти+ledger) + **baseline-normalization** (тренд XP за 7 дней vs собственный темп, label «высокий/средний/ниже»).
- **B — сделано:** `idle_tasks.py` (детерминированная агенда гигиены).
- **C — probing:** зафиксирован приоритет: event-log/read-model поверх имеющегося, baseline уже внедрён, детерминированный «поединок» воркеров отложен (пока нет сети).
- **Фикс попыток фабрики:** `rework_rounds` — попытка тратится только на реальную сдачу воркера, RETRY ревьюеров/тестеров попытку НЕ тратит (регрессия из ливня агента закрыта, тесты зелёные).

## Осторожность
- Не давать агенту «кликать» в idle-играх (это сжигает токены; исключение — opencode-сессии-логи).
- Fiz-запреты (permission deny edit/write) убраны — игра не должна быть приказом.
- Всё детерминировано: никакой LLM-генерации очков/уровней, только факты.
