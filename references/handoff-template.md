# Шаблон Handoff-пака (потеря кода между сессиями)

Образец-живой: `E:\Documents\Документы\writer-core\writer_core_handoff\` (MANIFEST.md + legacy_sources + правила).
Цель: продолжение работы в новой сессии без потери созданного кода. Оркестратор создаёт
handoff-пак в конце значимого этапа/задачи.

## Структура

```
handoff/<проект>-<дата>/
├── MANIFEST.md            # ИНДЕКС: что за проект, куда смотреть, код-статус
├── legacy_sources/        # snapshot созданного кода (копия src/, config/, tests/)
├── CHANGES.md             # что изменилось с прошлого handoff
├── TASKS.md               # открытые задачи, следующий шаг
├── DECISIONS.md           # архитектурные решения и почему
└── VALIDATION.md          # что проверено (тесты/ревью/фабрика)
```

## Что обязательно в MANIFEST.md
```markdown
# Handoff: <проект> от <дата>

## Иденти
- Репо/путь, git-статус, ветка
- Открытая сессия / task_id (если в фабрике)

## Где код
- Путь к работающему src/, config/, tests/ (в <HARNESS> или воркспейсе)
- snapshot в legacy_sources/

## Состояние
- Что сделано (ссылки на контракты, factory-статусы)
- Что не доделано / открытые замечания ревьюеров
- Что требует внимания человека

## Как продолжить
- Команда запуска тестов, factory_ctl status, чаршит
```

## Правила для оркестратора
1. В конце этапа задачи → создать `handoff/` в корне воркспейса (рядом с кодом).
2. `legacy_sources` = копия рабочего кода (src/config/tests), НЕ .git/venv/node_modules.
3. Git-коммит + ручной handoff — оба, если возможно. Git — авто-слои, handoff — читаемый для LLM документ.
4. На следующую сессию: открыть `MANIFEST.md` → продолжить по TASKS.md, а не «с нуля».
