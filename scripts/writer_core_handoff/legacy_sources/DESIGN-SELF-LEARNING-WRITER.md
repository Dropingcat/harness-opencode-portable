# Self-Learning Academic Writer (SLAW) — Architecture & Implementation

> Статус: **design v1** (зафиксировано 2026-09-03). Это исследовательская архитектура «лучшего писателя»: пишет что угодно сам, учится на лучших работах, использует лучшее из разных работ, всё в парадигме вложенных клаймов.
>
> Правило: **не упрощаем — хардкор**. Один источник правды — эта архитектура. Все блоки — модули writer-core.

---

## 0. Видение

Система, которая:
1. **Пишет что угодно**: статьи/longreads, диссертации, монографии, научные отчёты — через единое ядро + жанровые блоки.
2. **Учится на лучших работах**: локальный корпус референсов (статьи, диссертации, монографии) → извлечение клайм-графов, стилевых профилей, паттернов связанности.
3. **Использует лучшее из разных работ**: не копирует один источник, а комбинирует лучшие подходы (по клайм-графу и связанности).
4. **Проверяема**: каждая единица информации — клайм-узел с провенансом; сравнение с эталонами — через таблицу клаймов и граф связанности.

## 1. Парадигма: вложенные клаймы — единая модель всего

### 1.1 Все единицы информации — клаймы разного уровня

```
Уровень 0: ДОКУМЕНТ    (диссертация/статья/монография)
   └── Уровень 1: ГЛАВА/РАЗДЕЛ
        └── Уровень 2: ПАРАГРАФ (абзац)
             └── Уровень 3: ТЕЗИС (атомарное утверждение)
                  └── Уровень 4: ОБЪЕКТ (число, формула, термин, цитата)
```

**Ключевая идея**: нет «текста» и «данных» — есть единое дерево/граф клаймов разного размера. Число — клайм уровня 4. Тезис — уровень 3. Абзац — уровень 2 (композиция тезисов). Глава — уровень 1 (композиция абзацев).

### 1.2 Вложенность = иерархия + связи

- **PARENT_OF / CHILD_OF** — вложенность (абзац содержит тезисы; тезис содержит числа).
- **SUPPORTS / CONTRADICTS** — аргументация (тезис поддерживает тезис; evidence поддерживает claim).
- **DERIVED_FROM** — логика (вывод из посылок).
- **CITES** — провенанс (объект-цитата → источник).

### 1.3 Таблица клаймов (claim table)

Каждый документ (свой и эталонный) разворачивается в **таблицу клаймов**:

| Уровень | Тип юнита | Пример | Проверяемость |
|---|---|---|---|
| 0 | DOC | диссертация | структура ГОСТ |
| 1 | SECTION | глава 2 «Обзор литературы» | композиция |
| 2 | PARAGRAPH | абзац о механизме азотирования | связность тезисов |
| 3 | ASSERTION | «ε-фаза увеличивает износостойкость» | провенанс |
| 4 | OBJECT | число 12.5 мкм; формула; ГОСТ-ссылка | детерминированно |

Это и есть **функция сравнения**: эталон vs. черновик = сравнение таблиц клаймов (покрытие уровней, полнота, связность).

## 3. Модульная декомпозиция (блоки, не «один монолит»)

### M1. Genre Registry — жанровые блоки (НЕ однобоко)

Отдельные жанровые блоки, каждый со своей схемой:

| Жанр | Структура | Аппарат | ГОСТ |
|---|---|---|---|
| **longread** | интро → тезисы → аргументы → вывод | авторский голос, hook | нет жёсткого |
| **dissertation** (текущий) | введение → главы → заключение + приложения | ВАК: актуальность, объект/предмет, цель/задачи, гипотеза, новизна, положения, апробация | ГОСТ Р 7.0.11 |
| **monograph** | введение → части → главы → параграфы → заключение + аппарат | научный аппарат + авторская позиция | ГОСТ Р 7.0.5 |
| **научный отчёт** | аннотация → методология → результаты → выводы | IMRAD-профиль | ГОСТ 7.32 |

Каждый жанр = **схема структуры + правила аппарата + валидаторы структуры**. Внутри — общее ядро (клайм-граф), снаружи — жанровая специфика.

### M2. Claim-Graph Core (уже стартует в writer-core R0)

- WriterUnit (вложенные: DOC/SECTION/PARAGRAPH/ASSERTION/OBJECT)
- WriterTransaction (атомарность), WriterSnapshot (версии), event-log
- валидаторы: атомарность, провенанс, цитирование, стиль, консистентность
- **вложенность** (PARENT_OF/CHILD_OF) — обязательная связь для всех юнитов

### M3. Reference Learning Module (локальное обучение)

**Цель**: превратить корпус `F:\AnalisysDataSet\pdfs` (и статьи/дисеры/монографии) в обучающий ресурс.

Подмодули:
1. **Corpus Ingest**: PDF → текст → сегментация → клайм-извлечение (детерминированное + LLM-assisted) → клайм-граф каждого документа.
2. **Claim-Graph Extractor**: извлекает вложенный клайм-граф (уровни 1-4) из эталона.
3. **Style Profiler**: стилевой профиль документа (лексика, синтаксис, структура, риторика, ГОСТ-соответствие).
4. **Connectivity Analyzer**: граф связанности (как клаймы соединены смыслово: переходы, evidence→claim→conclusion).
5. **Pattern Library**: извлечённые повторяющиеся паттерны (аргументационные схемы, переходы, структурные ходы).
6. **Local Embedding Index**: векторный индекс (локально) для retrieval лучших фрагментов по запросу.

**Ключевое**: всё локально, без облака — учимся на собственном корпусе.

### M4. Comparison / Quality Engine (модуль сверки)

**Цель**: сравнить черновик с эталонами в нашей парадигме (таблица клаймов + граф связанности + стиль).

Функции:
1. **Claim-Table Comparison**: черновик → таблица клаймов; эталон → таблица клаймов; сравнение по:
   - покрытию уровней (0-4)
   - полноте (сколько тезисов/объектов на уровне)
   - связности (как клаймы связаны)
2. **Style Distance**: стилевой профиль черновика vs. эталона (векторное расстояние, без LLM-гадания).
3. **Connectivity Graph Comparison**: граф связанности черновика vs. эталона (изоморфизм/сходство).
4. **Gap Report**: что не дотягивает (нет объекта-числа там, где эталон имеет; слабая связность; стилевые расхождения).

### M5. Writer Adapter (генерация)

- Hermes writer (patch_planner → _grow_cells → state_machine → reverify) адаптируется под клайм-граф.
- Пишет юниты по плану (фреймер), юнит за юнитом, с валидацией каждого.
- Может использовать Reference Retriever (лучший фрагмент из корпуса по запросу) как подсказку стиля/структуры.

### M6. Review / Validation

- детерминированные валидаторы на юнит (атомарность, провенанс, цитирование ГОСТ, стиль, консистентность, объекты)
- self-check райтером → субагент-рецензент → APPROVED

### M7. Export

- юниты → Markdown (канонический порядок) → Pandoc → DOCX/PDF ГОСТ.

## 4. Стиль и граф связанности как функция сравнения

### 4.1 Что такое «стиль» в нашей парадигме

Не «красивые слова», а **структурно-связностный профиль**:

- **Синтаксис**: длина предложений, сложность, распределение.
- **Композиция абзацев**: сколько тезисов в абзаце, как они соединены.
- **Аргументационная плотность**: тезис/evidence/вывод на абзац.
- **Переходы**: как юниты связаны (коннекторы, отсылки, противопоставления).
- **Аппарат**: наличие и оформление научного аппарата (ГОСТ).
- **Риторические ходы**: вопрос-ответ, thesis-antithesis, определение-иллюстрация.

### 4.2 Граф связанности через клаймы

Каждый документ → **граф**: узлы = клаймы (разные уровни), рёбра = SUPPORTS/CONTRADICTS/DERIVED_FROM/CITES/PARENT_OF.

Связанность = мера того, как клаймы соединены. Лучшие работы имеют **плотный, глубокий, согласованный граф** (каждый тезис поддержан, каждый вывод выведен).

**Функция сравнения**:
```
similarity(draft, reference) = w1 * claim_table_similarity + w2 * style_distance + w3 * connectivity_graph_similarity
```

### 4.3 Копирование «подходов», не только стиля

**Паттерны связанности** (извлекаются из корпуса):
- «claim → 3 supporting evidence → conclusion» (аргументационная схема)
- «определение термина → числовая иллюстрация → следствие» (ход)
- «обзор → пробел (gap) → наш вклад» (структурный ход)
- «тезис → пример → ограничение» (нюансировка)

Эти паттерны — **не слова, а схемы связанности**. Writer берёт лучшие схемы из разных работ и собирает свой текст.

## 5. Подходы к реализации (hardcore)

### 5.1 Клайм-граф как единственная модель

- Все объекты (числа, формулы, термины, цитаты) — клайм-узлы уровня 4 с детерминированной проверкой (pint для единиц, LaTeX-парсер для формул, ГОСТ-валидатор для цитат).
- Вложенность обязательна: каждый юнит знает родителя (PARENT_OF) — это даёт «глубину» документа.

### 5.2 Локальное обучение на корпусе

1. **Ingestion pipeline**: PDF → (pypdf/pdfplumber) → текст → предложения → клайм-извлечение.
2. **Клайм-извлечение**: детерминированные правила (числа, единицы, ГОСТ-ссылки, формулы) + LLM-assisted (тезисы из абзацев, связи).
3. **Векторный индекс**: локальные embeddings (например, sentence-transformers / BGE) + sqlite-vector / faiss — retrieval «лучший фрагмент по запросу».
4. **Стилевой профиль**: статистический (не LLM): длины, лексика (TF-IDF), структурные маркеры.

### 5.3 Сравнение (детерминированное, не LLM)

- Таблица клаймов → покрытие/полнота/связность — чистые метрики.
- Стилевой профиль → косинусное/евклидово расстояние.
- Граф связанности → графовое сходство (Graph Edit Distance / WL-subtree kernel).
- Без «модель уверена» — числа.

### 5.4 Генерация с использованием лучшего

- Writer получает: план (фреймер) + writer_context (allowed/qualified/forbidden claims) + retrieval-подсказки (лучшие фрагменты) + паттерны связанности.
- Пишет юнит → валидатор → self-check → (опц.) рецензент → APPROVED → следующий юнит.
- Снэпшот перед каждым экспортом.

### 5.5 Исследовательские направления (то, что «ищем»)

1. **Паттерны связанности**: майнинг повторяющихся подграфов связанности в лучших работах → библиотека «ходов» (не слов, а схем).
2. **Перенос связанности**: перенос структурного «скелета» эталона на новый контент (не стиль, а подход к связыванию идей).
3. **Стиль через структуру**: стилевой перенос на уровне клайм-графа, а не на уровне слов.
4. **Комбинирование**: выбор лучшей схемы из работы A, лучшей связности из B, лучшего аппарата из C → сборка.
5. **Адаптация к жанру**: один клайм-граф, разные жанровые «линзы» (longread vs. диссертация vs. монография).

## 8. Решения, зафиксированные с пользователем

1. Отдельный проект writer-core (рядом с researcher).
2. Гранулярность: абзацы + утверждения + **объекты** (числа, формулы, термины).
3. Рецензирование: авто + self-check + субагент-рецензент.
4. Окружение: Python 3.12 + pydantic + pint.
5. Выход: MD + Pandoc (ГОСТ Р 7.0.5 / Р 7.0.11).
6. Язык: русский академический, ГОСТ.
7. Корпус эталонов: F:\AnalisysDataSet\pdfs (нужен дедуп).
8. **НЕ однобоко**: жанровые блоки (longread, диссертация, монография) с общим ядром.
9. **Самообучение**: локально на референсах (клайм-графы, стиль, паттерны связанности).
10. **Сверка**: через таблицу клаймов + граф связанности (функция сравнения).
11. **Вложенность клаймов**: числа → тезисы → абзацы → разделы → документ.
12. **Хардкор**: не упрощать; искать лучшие подходы копирования связанности (не только стиля).
