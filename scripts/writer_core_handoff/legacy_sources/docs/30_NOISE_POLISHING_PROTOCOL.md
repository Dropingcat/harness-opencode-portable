# 30. Noise Polishing Protocol — LLM-шлифовка шума детерминированного слоя

> Статус: **v0.1** (05.09.2026). Протокол итеративного тестирования и очистки шума
> детерминированных лингвистических эвристик через малую LLM (gemma-4-26b-a4b).

---

## 1. Зачем

Точность извлечения единиц информации определяет точность графа и вектора всей
работы (docs/26). Детерминированные эвристики (фигуры, хрия, суффиксы) дают шум —
ложные срабатывания. Малая LLM используется НЕ для извлечения, а для **фильтрации**
(шлифовки) уже извлечённого.

## 2. Принцип: разделение ролей

| Сущности | Инструмент | Почему |
|---|---|---|
| **Словесные сущности** (фигуры, хрия-части, акценты, связки) | детерминированные эвристики + **gemma-фильтр** | LLM хорошо определяет «это словесный приём или нет» |
| **Числовые метрики** (word_count, ratios, длины) | ТОЛЬКО детерминированный счётчик | gemma сама неточна в подсчёте (word_count ±1, ratio «не могу проверить») |
| **Объекты** (числа, химия, годы, цитаты) | ТОЛЬКО детерминированные (C5-C8) | LLM может галлюцинировать числа; regex точнее |

## 3. Протокол итеративного тестирования

```text
1. Случайная выборка N абзацев из эталона (автореферат).
2. Детерминированный слой: фигуры/хрия/морфо-счётчики/объекты.
3. gemma-фильтр (temp 0.0, строгий JSON):
   {"to_remove_figures": [idx], "to_remove_chreia": [idx], "comments": "..."}
4. Ручная/кодовая оценка: верно ли gemma удалила (precision фильтра).
5. Зафиксировать ошибки детерминированного слоя → фикстуры G-1.
6. Улучшить эвристики (расширить словари/суффиксы по замечаниям).
7. Повторить (iteration bump).
```

## 4. Результаты первого прогона (10 случайных абзацев Блинова)

| Метрика фильтра | Значение | Замечание |
|---|---|---|
| gemma-удаления ложных фигур/хрии: верных | **5/5** | ITER 1,4,5,10 — все корректны |
| gemma-удаления числовых метрик | **0/брать** | word_count/ratios НЕ чистить (LLM неточна) |
| Детерминированные объекты (числа/химия/годы) | точные | C5/C6/C7 верны даже в списках литературы |
| Хрия-рубрикатор | средний | ложно ловит тех. заголовки → фильтр обязателен |

## 5. Извлечённые уроки (обновляют эвристики)

1. **Парцелляция**: «Вязкость разрушения» (начало термина) — НЕ фигура; критерий: 
   парцелляция = короткое предложение ПОСЛЕ полного (с предл.), а не просто короткая строка.
2. **Хрия**: тех. заголовки и научные факты — НЕ части хрии (хрия = риторический ход, 
   не описание). Маркеры-suffixile: хрия-часть должна быть частью **аргументации**, 
   а не любого абзаца.
3. **Повтор**: в списках авторов/библиографии «Фамилия ×2» — НЕ фигура-повтор;
   фильтровать: повтор только в narrative-тексте (не в reference/literature).
4. **Морфология суффиксами**: расширены наборы nouns/verbs (сталь, данных, свойств, ...);
   для химических абзацев (много чисел/элементов) суффиксный метод ограничен —
   нужна лемматизация (rnnmorph) или gemma-леммы (в перспективе).

## 6. Контракт gemma-фильтра (strange schema)

```yaml
# Запрос (1 вызов на абзац)
input:
  text: "..."
  det: {figures: [...], chreia: [...], connectors: [...], emphasis: [...]}
  model: google/gemma-4-26b-a4b-it
  temperature: 0.0
output:
  to_remove_figures: [индексы false-positive]
  to_remove_chreia: [индексы false-positive]
  comments: "..."
```
