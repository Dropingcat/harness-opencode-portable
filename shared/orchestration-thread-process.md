# Orchestration Thread Process — единая капсула «нити разработки» для всех оркестраторов

> **Источник истины для всех primary-оркестраторов**: `code-orchestrator`, `research-orchestrator`, `writing-orchestrator`.
> Цель капсулы — вернуть агенту **нить разработки**: канбан, трекер (WS/TD), память L3, архитектурные порталы, состояние фабрики.
> Проблема, которую она решает: оркестратор забывает архитектуру проекта, капсулируется в текущей задаче и бесконечно уходит в микрозадачу.

Этот файл — **shared** (не agent-specific). Оркестраторы ссылаются на него в начале и закрытии задач.

---

## 1. Зачем это

Без явного ритуала LLM-оркестратор:
- теряет «где я в большом каркасе» уже на 2-й итерации;
- не видит, какие WS/TD/канбан-статусы открыты;
- не связывает текущий модуль с архитектурой (portal docs);
- молча «додумывает» скоуп вместо вопроса пользователю.

Капсула делает нить **явной и детерминированной**: один скрипт (`project_context.py`) даёт снимок, два ритуала (старт/закрытие) вынуждают читать и писать.

---

## 2. Единый снимок нити (`project_context.py`)

```
python "${OPENCODE_HARNESS_ROOT}/scripts/orchestration/project_context.py"
```

Возвращает JSON: `kanban` (последние статусы), `tech_debt` (открытые TD), `tracker` (открытые пункты **IMPLEMENTATION_TRACKER.md** по WS), `memory_l3` (уроки), `factory` (состояние фабрики), `portal_docs` (архитектурные докyменты, существующие в HARNESS).

> Это **read-only**. Снимок — для ориентировки; закрытие пунктов — отдельными правками (см. ритуал закрытия).

Команда для геймификационного контекста (опционально):
```
python "${OPENCODE_HARNESS_ROOT}/scripts/orchestration/character_sheet.py" --min
```

---

## 3. Ритуал старта (ОБЯЗАТЕЛЬНО, перед декомпозицией/первым диспатчем)

1. Вызови `project_context.py` и прочитай вывод.
2. Прочитай 1–2 **релевантных** документа из `portal_docs` (ARCHITECTURE / MANIFEST / GLOBAL_TASK_CONTROLLER / CAPABILITY_REGISTRY / свой domain-процесс). **Не пропускай.**
3. Проговори (в reasoning) «Где я»:
   - какой **WS-пункт** трекера закрываю (или какой создаю);
   - какие **TD-**: трогаю/не трогаю;
   - статус в **канбане** (`task_id` для этой задачи);
   - как **эта задача** вписывается в архитектуру (связь одним предложением).
4. Если связь с дорожной картой не находится — спроси пользователя (`question`), а не додумывай молча.
5. Проверь память: `memory` (mode=search) по ключевым словам + уроки из `memory_l3`.

---

## 4. Ритуал закрытия (ОБЯЗАТЕЛЬНО, перед итоговым отчётом)

1. **Канбан**: отчитайся в глобальный трекер — **канонический хелпер с реестром секций**:
   ```bash
   python "${OPENCODE_HARNESS_ROOT}/scripts/orchestration/kanban_report.py" report <agent_id> <task_id> <status> [phase] [progress] [message]
   ```
   > **agent_id — СВОЙ (по контуру), НЕ единый code-factory.** Реестр секций:
   > `code-factory` (код), `writing` (writing-orchestrator, article-writer),
   > `research` (research-orchestrator, claim-parser, fact-checker...), `infra`.
   > Хелпер сам регистрирует агента с правильной `group_name` (секцией).
   > Доска по секциям: `kanban_report.py board [group]`; сводка: `kanban_report.py`.
   > Старая сигнатура `gk.report(agent, task_id, task_name, status, phase, ...)` НЕВЕРНА
   > (позиционные аргументы не совпадают) — не используй её.
2. **Трекер/долги**: если закрыл пункт — отметь:
   - `IMPLEMENTATION_TRACKER.md`: `- [ ]` → `- [x]`;
   - `config/tech_debt.json`: `"status":"open"` → `"closed"` (с датой/нотой).
3. **Память L3**: если в задаче накопился урок — добавь через детерминированный канал (`scripts/memory/memory_bridge.py add` — пути ASCII junction).
4. **Контроль остатка**: перезапусти `project_context.py`; в отчёте укажи, сколько WS/TD осталось открыто.

---

## 5. Анти-капсуляция (ограничение фокуса)

- **Лимит погружения:** >3 уточнений/ревью одного модуля ИЛИ при повторном «забыл архитектуру» → СТОП: перечитай `project_context.py` + 1 портальный док, обнови план, потом continue.
- **Вне-скоупа:** новая проблема вне текущей задачи → зафиксируй в трекер/tech_debt (TD-*), НЕ исправляй сейчас.
- **Бюджет фокуса:** каждый отчёт содержит «Остаток нити: N WS, M TD открыто».
- **Возврат:** осознал потерю нити → немедленно `project_context.py` + перечитывание портала, затем continue.

## 6. Формат «Где я» в отчёте (обязательная строка)

```markdown
**Где я:** WS-<номер> / TD-<номер> / канбан <task_id>; связь с архитектурой: <одна фраза>
**Остаток нити:** <N WS открыто, M TD открыто — из project_context.py>
```

## 7. Domain-специфика

| Оркестратор | Шаги старта дополнительно | Шаги закрытия дополнительно |
|---|---|---|
| `code-orchestrator` | снимок фабрики (`factory`), состояния попыток/переработок; GC-формат отчёта | GC-отчёт в канбан; закрытие WS/TD; git-коммит-гейт уже в `factory_ctl submit` |
| `research-orchestrator` | статус research-контура (runner есть/нет, `RESEARCH_*` vars); какой WS-пункт research | канбан-отчёт по исследованию; закрыть исследовательские WBS; сохранить урок про источники |
| `writing-orchestrator` | статус портальных доков писателя (`writing-orchestration-process.md`), жанр/капсулу | канбан-отчёт; сохранить что-то полезное для следующих статей; закрыть TD-пункты писателя |
