# Research Process — дисковый протокол для research-агентов

> Shared-контракт для `researcher.md`, `article-writer.md` и любых агентов,
> которые ведут research-каталог. Покрывает **где приземляются артефакты** (RESEARCH_DIR)
> и **какие инструменты реально доступны** для поиска/верификации.

## RESEARCH_DIR (правило резолюции)

```
RESEARCH_DIR = ${RESEARCH_DIR:-${OPENCODE_HARNESS_ROOT}/research}
```

Приоритет:
1. `$RESEARCH_DIR` (если задан в env).
2. `${OPENCODE_HARNESS_ROOT}/research` (canonical, создаётся при первом использовании).
3. Локальная папка `research/` в текущем воркспейсе, если пользователь явно туда велел.

Оркестратор (или агент) создаёт папку при необходимости:
```
mkdir -p "$RESEARCH_DIR"/{notes,reports,articles}
```

## Структура

```
research/
├── notes/      # заметки, наблюдения, инсайты (внешние знания)
├── reports/    # research-отчёты: reports/[topic-slug]-[YYYY-MM-DD].md
└── articles/   # готовые статьи: articles/[topic-slug]-article-[YYYY-MM-DD].md
```

## Инструменты (что реально есть, а не «на бумаге»)

| Инструмент | Назначение | Статус |
|---|---|---|
| `webfetch` | чтение известного URL → markdown | ✅ доступен |
| `research_papers` | arXiv + OpenAlex поиск | ✅ (если сконфигурирован в runtime) |
| `search` / searxng MCP | веб-поиск | по наличию runtime |
| `tvly` (Tavily CLI) | CLI-поиск/извлечение | ⚠️ **опционально;** если не установлен — НЕ использовать, заменить `webfetch`/`search` |
| `read`/`write`/`edit` | чтение/запись артефактов | ✅ |

> **Правило:** НЕ полагайся на `tvly`, если он отсутствует на машине. Проверяй `which tvly`
> (или `shutil.which`), иначе используй `webfetch` + `search`. Никогда не паникуй «нет инструмента» —
> фолбэки перечислены выше.

## Верификация фактов (для article-writer/researcher)

1. Каждое важное фактическое утверждение — из источника (URL) или явного вывода с указанием неопределённости.
2. Нет источника → пометь как inference/caveat, либо проверь `webfetch`/`search`, либо удали.
3. Не выдумывать URL/цитаты/статистику — только то, что реально прочитано.
4. Расхождения источников сохранять явными, не сглаживать в ложный консенсус.

## Output

- Research-отчёт: `reports/[topic-slug]-[YYYY-MM-DD].md` (структурировано: вопрос, находки, источники, лакуны).
- Статья (если просили сохранить): `articles/[topic-slug]-article-[YYYY-MM-DD].md`.
- Возвращаемое агентом: краткое резюме + путь к файлу (если писал).
