# Search Depth Contract — контракт глубины поиска (TD-170)

**Цель:** агент НЕ «вспоминает» контекст посреди поиска, а по циклу: зафиксировать → осмотреться → оценить глубину → идти дальше.

## Цикл поиска (всегда)

```
1. ЗАФИКСИРОВАТЬ — что нашёл прямо сейчас → записать в артефакт (sources_<id>.json / prov.json / заметку).
2. ОСМОТРЕТЬСЯ — какие ещё источники/каналы доступны ВОКРУГ (список ниже).
3. ОЦЕНИТЬ ГЛУБИНУ — сколько ещё реально нужно для ТЕКУЩЕЙ задачи (критерий остановки).
4. ИДТИ ДАЛЬШЕ — следующий канал или завершить с verdict; НЕ перепроверять найденное без нужды.
```

## Оценка задачи (skill)

Перед поиском ответь на 4 вопроса (в контракте задачи):
1. **Что ищем?** (конкретный факт / полный текст / TOC / DOI / ISBN)
2. **Зачем?** (для какого claim/BRICK — какая точность нужна)
3. **Сколько нужно?** (1 источник / 3-5 / исчерпывающе)
4. **Когда достаточно?** (критерий остановки: напр. «TOC хватает для B1», «нужен полный текст — иначе not_found»)

## Глубины поиска

| Глубина | Каналы | Когда |
|---|---|---|
| **поверхностный** | 1 канал (локальный корпус ИЛИ первый релевантный) | факт из памяти/корпуса, быстрый ответ |
| **средний** | 3-5 (corpus → arxiv/openalex → searxng/webfetch → downloader resolve) | стандартная верификация claim |
| **глубокий** | все + mirror-обходы (libgen/annas/lib-bkm, DNS-bypass, captcha-маркер) | полный текст/книга/редкий источник |

## Каналы поиска (осмотреться вокруг)

### Статьи / научные
- локальный корпус (`chroma_indexer`), arXiv (`arxiv_search`), OpenAlex (`openalex_search`), веб (`searxng_search`/webfetch), DOI→Sci-Hub (`downloader resolve`), Sci-Bot API

### Книги / ГОСТы / справочники
- `book_finder` (resolve-isbn → dokumen/vdoc/libgen/annas → verdict)
- **lib-bkm.ru** (Библиотека Машиностроителя): каталог `/load/104` (Материаловедение), `/load/25` (ГОСТы), `/load/135` (Диссертации), `/load/105` (Станки) — сканирование категории постранично
- ГОСТ-каталоги: `gost_collector` (маппинг марок), БНТУ-библиотека (TOC), РГБ

### Окрестность (всегда смотреть)
- Что ещё в той же категории каталога (соседние файлы)
- Смежные разделы (ГОСТы рядом со справочниками)
- Кто цитирует/ссылается (перекрёстные ссылки в TOC/литературе)

## Критерий остановки

- Достиг цели (верdict found / toc_only достаточно / claim покрыт)
- Исчерпал каналы выбранной глубины → честный `not_found` с провенансом
- **НЕ:** зацикливаться на одном канале, «вспоминать» контекст, перепроверять найденное

## Проверка (применимо к поиску книги)

- Нашёл TOC → записал TOC в артефакт → осмотрелся (lib-bkm, ГОСТ-каталог) → оценил: для B1 нужен ли полный текст? → если нет → verdict `toc_only` и дальше. Без curl-петель.

## Запись для поискового агента (TD-177) — «осмотреться вокруг»

> Правило: **НЕ «вспоминать» контекст посреди поиска.** Нашёл частично что-то → ЗАПИШИ находку в артефакт → ОСМОТРИСЬ, какие ещё источники доступны вокруг → ОЦЕНИ глубину (контракт выше) → ИДИ ДАЛЬШЕ.

### Перед поиском (skill оценки задачи + контекста, TD-177)

1. **Оцени задачу** (4 вопроса):
   - Что ищем? (конкретный факт / полный текст / TOC / DOI / ISBN)
   - Зачем? (для какого claim/BRICK — какая точность нужна)
   - Сколько нужно? (1 источник / 3-5 / исчерпывающе)
   - Когда достаточно? (критерий остановки)
2. **Оцени контекст** (что уже есть):
   - Что уже нашли в этой сессии? (не перепроверять)
   - Что лежит рядом в корпусе/каталогах? (соседние файлы той же категории, смежные разделы ГОСТ/справочников)
   - Какие каналы доступны? (список в разделе «Каналы поиска» выше)
3. **Выбери глубину** (поверхностный/средний/глубокий) и зафиксируй её в контракте задачи.

### Во время поиска

- Нашёл частичный результат → **сразу записать в артефакт** (`sources_<id>.json` / prov.json / заметку). Не держать в голове.
- Осмотреться: какие ещё каналы/источники доступны вокруг (список выше).
- Оценить: сколько ещё реально нужно для ТЕКУЩЕЙ задачи (критерий остановки).
- Идти дальше (следующий канал) ИЛИ завершить с честным `verdict` (`found` / `toc_only` / `not_found`).

### Запрещено

- Зацикливаться на одном канале (curl-петли, повторные retry одного зеркала).
- «Вспоминать» контекст вместо записи в артефакт.
- Перепроверять уже найденное без нужды.
- Углубляться (глубокий поиск), когда для текущего claim достаточно TOC/поверхностного.
