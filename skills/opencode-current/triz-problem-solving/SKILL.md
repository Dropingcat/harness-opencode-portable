# TRIZ Problem Solving

## Overview

База знаний ТРИЗ (Theory of Inventive Problem Solving / Теория решения изобретательских задач) для агентов opencode. Извлечена из production-архива `triz-agent` (v2.1.1, 494+ тестов). Содержит:

- **18 принципов ТРИЗ** (срез из 40) — приёмы разрешения противоречий.
- **Матрицу противоречий** (7 пар + generic fallback) — выбор принципов по паре «улучшаемый/ухудшаемый параметр».
- **Шаблоны ИКР** (3 шт.) — идеальный конечный результат без указания способа.
- **Ресурсы ВПР** (6 категорий) — вещественно-полевые ресурсы.

Skill предназначен для трёх ролей:

- **experimenter** — оптимизация параметров, поиск противоречий в экспериментах.
- **code-orchestrator** — архитектурные решения, разрешение конфликтов требований.
- **research-orchestrator** — формулировка исследовательских задач, поиск ресурсов.

## When to Use

Активировать, когда задача содержит:

- Противоречие: «если улучшить A, то ухудшается B», «нужно и то, и другое одновременно».
- Оптимизацию: trade-off, компромисс, конфликт требований.
- Дизайн/архитектуру: выбор структуры, модульности, распределения.
- Поиск идеального результата: «как должно быть идеально».
- Поиск ресурсов: «что уже есть в системе, что можно использовать».

Если нет противоречия — нет задачи (принцип супервизора из SOUL.md).

## Core Workflows

### 1. Найти противоречие (Find the contradiction)

Сформулируй пару «улучшаемый параметр / ухудшаемый параметр». Без противоречия задача не решается через ТРИЗ.

```
Если улучшить {A}, то ухудшается {B}.
```

### 2. Выбрать пару из матрицы (Select from contradiction matrix)

Найди пару в `CONTRADICTION_MATRIX` (7 пар). Если пары нет — используй `GENERIC_FALLBACK` (разделение физического противоречия).

| Пара (улучшаемый / ухудшаемый) | Принципы |
|--------------------------------|----------|
| скорость / качество | [10, 19, 24] |
| дробление / координация | [1, 5, 7] |
| универсальность / эффективность | [7, 3, 40] |
| автономность / контроль | [24, 23, 11] |
| точность / стоимость | [1, 26, 22] |
| объём данных / скорость | [19, 20, 28] |
| сложность / надёжность | [11, 27, 35] |

**Generic fallback** (разделение физического противоречия):

| Категория | Принципы |
|-----------|----------|
| разделение_во_времени | [19, 15] |
| разделение_в_пространстве | [1, 17] |
| разделение_в_системе | [7, 24] |
| разделение_по_условию | [35, 3] |

### 3. Применить принципы (Apply principles)

Для каждого номера принципа из матрицы — прочитай описание и примеры из раздела «18 принципов ТРИЗ» ниже. Примени 2–3 принципа к противоречию.

### 4. Сформулировать ИКР (Formulate IFR)

Используй шаблоны ИКР (идеальный конечный результат). **Запрещено** использовать слова «нужно», «следует», «применить» — ИКР описывает результат, а не способ.

### 5. Проверить ресурсы (Check VPR resources)

Прежде чем добавлять новое — посмотри, что уже есть в системе (принцип супервизора). Пройди по 6 категориям ресурсов ВПР.

## 18 принципов ТРИЗ (TRIZ Principles)

| № | Принцип | Описание | Примеры |
|---|---------|----------|---------|
| 1 | Дробление (Segmentation) | Разделить объект на независимые части | Разделить задачу на подзадачи; систему на модули; данные на блоки |
| 2 | Извлечение (Extraction) | Выделить мешающую часть или свойство | Извлечь шум из сигнала; ошибку из кода; ключевую информацию из текста |
| 3 | Местное качество (Local Quality) | Разные части объекта должны иметь разные функции | Разные агенты выполняют разные задачи; модули оптимизированы под разные операции; данные в разных форматах |
| 4 | Асимметрия (Asymmetry) | Заменить симметричную форму асимметричной | Асимметричная структура данных; несимметричное распределение нагрузки; асимметричная архитектура |
| 5 | Объединение (Consolidation) | Сблизить одинаковые или родственные объекты | Объединить похожие задачи; данные из разных источников; результаты анализа |
| 7 | Матрёшка (Nesting) | Объект вложен в другой, который вложен в третий | Функция внутри функции; модуль внутри модуля; задача внутри задачи |
| 10 | Предварительное исполнение (Prior Action) | Заранее выполнить действие | Предварительная обработка данных; предварительный анализ задачи; предварительная валидация |
| 11 | Подушка безопасности (Cushion) | Заранее подготовить средства против отказа | Circuit breaker для API; fallback-модель; резервное копирование |
| 13 | Наоборот (Inversion) | Вместо требуемого действия реализовать обратное | Вместо добавления — удаление; усложнения — упрощение; централизации — децентрализация |
| 15 | Динамичность (Dynamization) | Объект должен меняться для оптимальной работы | Адаптивные алгоритмы; динамическая маршрутизация; адаптивная загрузка контекста |
| 17 | Другое измерение (Another Dimension) | Перейти в другое измерение | 2D → 3D визуализация; линейный → параллельный процесс; последовательный → итеративный подход |
| 19 | Периодическое действие (Periodic Action) | Заменить непрерывное действие периодическим | Cron-задачи вместо непрерывного мониторинга; периодическая проверка качества; периодическое обновление данных |
| 22 | Обратить вред в пользу (Blessing in Disguise) | Использовать вредные факторы для положительного эффекта | Использовать ошибки для улучшения; ограничения как стимул; шум для тестирования |
| 24 | Посредник (Intermediary) | Использовать промежуточный объект | Канбан как посредник между задачами; API-шлюз; кэш |
| 26 | Копирование (Copying) | Заменить дорогой объект дешёвой копией | Кэширование вместо повторных вычислений; мок-объекты; упрощённые модели |
| 28 | Замена механической системы (Mechanics Substitution) | Заменить механическую систему физической/химической | Ручную обработку — автоматической; текстовый интерфейс — графическим; последовательный процесс — параллельным |
| 35 | Изменение параметров (Parameter Change) | Изменить агрегатное состояние, концентрацию, гибкость | Изменить temperature модели; размер контекста; порог качества |
| 40 | Композитные материалы (Composite Materials) | Заменить однородный материал композитным | Композитная архитектура (микро- + макро-); композитные данные; композитные модели (LLM + rule-based) |

## Шаблоны ИКР (IFR Templates)

Идеальный конечный результат — состояние, при котором система сама выполняет нужную функцию, не требуя дополнительных ресурсов. **Запрещено** указывать способ достижения.

1. `Система сама делает {X}, не требуя дополнительных ресурсов`
2. `{Объект} сам выполняет {функцию} за счёт использования внутренних ресурсов`
3. `Результат {Y} достигается без усложнения системы`

## Ресурсы ВПР (VPR Resources)

Вещественно-полевые ресурсы — 6 категорий. Прежде чем добавлять новое, проверь, что уже есть в системе.

| Категория | Описание | Примеры |
|-----------|----------|---------|
| вещественные (substance) | Материальные объекты, поля, вещества | данные, файлы, модели, коды |
| полевые (field) | Физические поля (гравитационное, электромагнитное) | API, сети, базы данных, облачные сервисы |
| информационные (information) | Данные, знания, алгоритмы | документация, логи, метрики, конфигурации |
| функциональные (functional) | Способности системы выполнять действия | навыки агентов, инструменты, функции |
| временные (time) | Паузы, интервалы, задержки | время выполнения, таймауты, расписания |
| пространственные (space) | Пустоты, полости, зазоры | директории, контейнеры, виртуальные среды |

## Integration

- **ariz-contradiction-resolution** — для полного 8-шагового процесса АРИЗ (этот skill даёт knowledge base, АРИЗ даёт workflow).
- **adversarial-critic-checklist** — для критической проверки сформулированных решений и ИКР.

## Common Pitfalls

- **ИКР с глаголами-нарушителями** — «нужно», «следует», «применить» запрещены в ИКР (описывают способ, а не результат).
- **Нет противоречия** — если не можешь сформулировать пару «улучшаемый/ухудшаемый», задача не готова для ТРИЗ.
- **Пропуск ресурсов** — всегда проверяй 6 категорий ВПР перед добавлением нового.
- **Один принцип** — применяй 2–3 принципа, не останавливайся на первом.
