# Sci-Bot: подбор статей, выжимки, мини-обзоры

**Сайт:** https://sci-bot.ru
**Что это:** платный AI-ассистент с доступом к Sci-Hub. Подбирает статьи по тематике, отвечает с ГОСТ-цитатами и DOI.

**Важно:** это **платный** ресурс — токены аккаунта пользователя общие и ограниченные. Экономия токенов обязательна.

---

## КОНТРАКТ ИСПОЛЬЗОВАНИЯ (НЕ НАРУШАТЬ)

### 1. Разрешённые типы запросов (ТОЛЬКО эти)

| Тип | Пример запроса | Ожидаемый результат |
|---|---|---|
| Подбор статей по тематике | «Подготовь статьи по тематике …» / «Мне нужны статьи из области …» | Список статей: title, авторы, год, DOI, краткая аннотация |
| Краткая выжимка из статьи | «Дай краткую выжимку по статье …» | 5-15 предложений: суть, методы, ключевые результаты, DOI |
| Мини-обзор по статьям | «Сделай мини-обзор по …» / «Обзор статей по теме …» | Сгруппированный по темам обзор с DOI-ссылками, 300-800 слов |

### 2. Запрещено (НЕ использовать Sci-Bot для этого)

- ❌ Open-ended вопросы и общие консультации («что ты думаешь про…?», «объясни…»)
- ❌ Полные тексты статей и постраничные переводы
- ❌ Запросы, не относящиеся к подбору/выжимке/обзору научных статей
- ❌ Повторные отправки одного и того же вопроса (дедупликация запрещает)

### 3. Форма запроса — ЧЁТКИЙ ЧЕЛОВЕЧЕСКИЙ ЗАПРОС

Правильная формулировка — из разряда:

- «Подготовь статьи по тематике: <тема>»
- «Мне нужны статьи из области: <область>»
- «Найди и кратко опиши ключевые работы по <теме>»
- «Дай выжимку по статье <название/DOI>»
- «Сделай мини-обзор по <теме>»

Формулировка всегда: конкретная тема/область/название + желаемый результат (список / выжимка / обзор).

### 4. Лимиты и экономия токенов

1. **Только режим `conversation`** (дешёвый, ~20K токенов). Режим `chat` (~180K) ЗАПРЕЩЁН.
2. **Один запрос = один вопрос.** Не дублировать, не переспрашивать одно и то же.
3. **Floor = 300 000 токенов** — ниже этого баланса клиент не отправляет.
4. Ожидаемый расход > 30K токенов — спросить разрешение у пользователя.
5. Токены — общий ограниченный ресурс. Без явной необходимости не использовать.
6. Максимум 2 итерации на вопрос. После 2-й — сообщить пользователю и спросить, нужен ли ещё запрос.

## Как запустить

```bash
python scripts/sci_bot_client.py "<ВОПРОС НА РУССКОМ>" [--max-burn 30000] [--floor 300000] [--out /путь/к/ответу.md]
```

Зависимости: `websockets` (установлен в venv Hermes), cookie авторизации вшита в клиент.

> **Linux-заметка:** на оригинальном сервере клиент лежит в `/home/orangepi/.hermes/profiles/resercher/skills/sci-bot-search/sci_bot_client.py`, интерпретатор — `/home/orangepi/.hermes/hermes-agent/venv/bin/python3`. На Windows используй `python` из venv harness (`.venv\Scripts\python.exe`).

## Что вернуть

Клиент печатает JSON-строку вида:
```json
{"ok": true, "answer_len": 1683, "cot_len": 1455, "time_s": 27.8,
 "turn_tokens": 19540, "balance_before": 1401570, "balance_after": 1382030,
 "burn": 19540, "file": "/tmp/opencode/sci_answer.md"}
```

- `ok:true` → прочитать `<out>` (чистый ответ markdown с цитатами) и `<out>_cot.md` (внутренние размышления бота, справочно).
- `ok:false` → **НЕ повторять вопрос**. Причина в `reason` («дубль» / «баланс ниже floor»).

Из ответа извлеки: основные положения, конкретные числа, DOI-ссылки. Формат возврата — JSON с `sources: [{title, doi, year, trust, relevance}]`.

## Ошибки

- `TIMEOUT 300s` — бот долго думает (обычно 20-40с). Допускается до 2 попыток одного вопроса, НО только если ответ не был получен.
- `вопрос уже отправлялся ранее (дубль)` — стоп, искать другой источник.
- Баланс растёт/падает скачками — токены списываются за фактические вычисления (`cacheMissTokens`). Уточнять у пользователя перед новым запросом.

## Doom loop

Макс 2 итерации на вопрос. После 2-й — сообщить пользователю и спросить, нужен ли ещё запрос (это стоит токенов).
