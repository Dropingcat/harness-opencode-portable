## 1. Цели и границы ответственности
**Цель:** Реализовать механизм контроля *процедуры исполнения*, который детектирует имитацию работы, хаки, лень и нарушения регламента, опираясь на метаданные и метрики, а не на семантику артефактов.  
**Границы:**
*   ✅ **Входит:** Триггерная логика, анализ `ProcessMetrics` и `Trace`, детекция паттернов обмана, генерация процессных рекомендаций.
*   ❌ **Не входит:** Оценка качества кода, генерация фиксов, запуск инструментов верификации, принятие решений о завершении задачи.

> ⚠️ **Железное правило АРИЗ:** Аудитор **НИКОГДА** не читает содержимое файлов в `Artifact.files`. Он видит только хэши, диффы (как числа/структуры), логи и метрики. Если аудитор начал парсить код — это баг.

## 3. Детальные требования к компонентам

### 3.1. Audit Triggers (`audit_triggers.py`)
Детерминированная логика принятия решения: «Вызывать ли аудитора сейчас?»

**Требования:**
1.  Функция `should_audit(iteration: int, metrics: ProcessMetrics, last_critic_verdict: Verdict, config: Dict) -> bool`.
2.  **Условия вызова (OR-логика):**
    *   `iteration % config['audit_interval'] == 0` (например, каждые 3 итерации).
    *   `metrics.fix_repetition_rate > config['stagnation_threshold']` (осцилляция).
    *   `last_critic_verdict == Verdict.AMBIGUOUS`.
    *   Явный флаг `force_audit` от пользователя/оркестратора.
3.  **Жесткий запрет:** Никогда не возвращать `True` при `iteration == 1`.
4.  Конфигурация порогов загружается из `config.yaml`, значения по умолчанию заданы в коде.

**Почему это важно:** Аудитор — дорогая операция (даже без LLM). Бесполезные вызовы создают шум и замедляют цикл.

### 3.2. Pattern Detectors (`patterns/`)
Каждый паттерн — отдельная чистая функция. Никакого состояния.

#### `anti_hack.py`
| Паттерн | Входные данные | Логика детекции | Severity |
| :--- | :--- | :--- | :--- |
| Test Modification | `trace[-1].artifact_hash`, `prev_artifact_hash`, `file_list_diff` | Изменен файл, matching `test_*` или `*_test` | BLOCK |
| Context Tampering | `context_diff` (если доступен) | Изменены входные файлы контекста без явного разрешения | BLOCK |
| Verifier Bypass | `tool_results_summary` | Верификатор не запущен или вернул пустой результат при наличии кода | WARNING |

#### `anti_lazy.py`
| Паттерн | Входные данные | Логика детекции | Severity |
| :--- | :--- | :--- | :--- |
| Cosmetic Change | `semantic_diff_ratio` | Ratio < `min_meaningful_change` (конфиг, default=0.05) | WARNING |
| Oscillation | `fix_repetition_rate` | Rate > `oscillation_threshold` (default=0.6) за последние 3 итерации | BLOCK |
| No Progress | `log_completeness`, `metrics_snapshot` | Метрики не улучшаются 2+ итерации подряд | WARNING |

#### `anti_performative.py`
| Паттерн | Входные данные | Логика детекции | Severity |
| :--- | :--- | :--- | :--- |
| Complexity Bloat | `lines_added`, `test_pass_rate` | Строки растут, но pass_rate не растет | WARNING |
| Tool Churn | `tool_usage_consistency` | Частая смена инструментов без улучшения метрик | WARNING |

**⚠️ Контроль ошибок:**
*   Все функции принимают **только** структурированные данные (метрики, хэши, списки файлов). **Никакого содержимого файлов.**
*   При отсутствии данных (например, нет предыдущего артефакта) функция возвращает `None` (не violation), а не бросает исключение.

### 3.3. Auditor Core (`auditor.py`)
Собирает триггеры и паттерны в единый отчет.

**Требования:**
1.  Класс `ProcessAuditor`, реализующий протокол `Agent` (или Callable).
2.  Метод `analyze(trace: List[TraceEntry], metrics: ProcessMetrics, config: Dict) -> AuditReport`.
3.  **Логика:**
    *   Прогоняет все pattern detectors.
    *   Собирает violations.
    *   Определяет `block`: True если есть хотя бы один violation с severity=BLOCK.
    *   Генерирует `recommendations`: список строк на основе detected patterns (шаблоны из конфига).
    *   **НЕ** генерирует fix_notes для кодера.
4.  Возвращает строго `AuditReport` из WP-0.
5.  Время выполнения < 10ms на 100 итераций трассы.

**Важно:** Рекомендации должны быть *процессными*:
*   ✅ "Increase context window", "Request user clarification", "Reset fix_notes history"
*   ❌ "Fix variable naming", "Add error handling", "Refactor function"

## 4. Критерии приемки (Definition of Done)

### 4.1. Функциональные
- [ ] Триггеры корректно срабатывают на стагнацию, ambiguous и интервал.
- [ ] Триггер никогда не срабатывает на 1-й итерации.
- [ ] Anti-hack детектирует изменение тестового файла по имени.
- [ ] Anti-lazy детектирует косметические правки по semantic_diff_ratio.
- [ ] Anti-performative детектирует рост сложности без улучшения тестов.
- [ ] Аудитор возвращает валидный `AuditReport` при любом входе.
- [ ] Аудитор **не читает содержимое файлов** (проверяется code review + тестами).

### 4.2. Тестовые
- [ ] Unit-тесты для каждого паттерна (≥ 3 позитивных + 3 негативных кейса).
- [ ] Integration-тест: синтетическая трасса с известным нарушением → корректный block/recommendation.
- [ ] Property-based тест: любая валидная трасса не вызывает crash аудитора.
- [ ] Performance-тест: 100 итераций трассы анализируются за < 10ms.

### 4.3. Структурные
- [ ] Нет импортов моделей артефактов (только TraceEntry, ProcessMetrics).
- [ ] Паттерны вынесены в отдельные функции/модули.
- [ ] Конфигурация порогов внешняя.
- [ ] Type hints полные, mypy strict passes.

## 5. Риски и митигации

| Риск | Вероятность | Влияние | Митигация |
| :--- | :--- | :--- | :--- |
| Аудитор начинает оценивать код | Высокая | Дублирование критика, нарушение архитектуры | Code review. Тест "no file content access". Жесткое разделение типов. |
| Ложные блокировки на валидных задачах | Средняя | Остановка продуктивной работы | Конфигурируемые пороги. Режим `strict=False` по умолчанию. Логирование причин. |
| Паттерны слишком примитивны | Средняя | Пропуск реальных хаков | Итеративное улучшение. Сбор false negatives в production. Meta-auditor (future). |
| Аудитор падает на битых данных | Низкая | Остановка цикла | Defensive coding. Все паттерны обернуты в try/except с дефолтным результатом. |
| Рекомендации бесполезны | Средняя | Декоративность аудитора | Шаблоны рекомендаций утверждены заранее. Привязка рекомендации к конкретному паттерну. |

## 8. Чек-лист для ревьюера (КРИТИЧЕСКИЙ)

- [ ] **NO CODE READING:** В `auditor.py` и `patterns/` нет доступа к `Artifact.files.values()`, `content`, `source_code`. Только хэши, имена файлов, числовые метрики.
- [ ] **NO FIX SUGGESTIONS:** В `recommendations` нет советов по коду. Только процессные действия.
- [ ] **DETERMINISTIC:** При одинаковой трассе и метриках результат идентичен.
- [ ] **SAFE DEFAULTS:** При ошибке в паттерне аудит не блокирует задачу (fail-open для warnings, fail-closed только для явных BLOCK-паттернов).
- [ ] **TRIGGER GUARD:** `iteration == 1` всегда возвращает `False` в `should_audit`.
- [ ] **SCHEMA COMPLIANCE:** Возвращаемый `AuditReport` проходит валидацию Pydantic.
