# ARCHITECTURE.md: Архитектурные решения v0.2

> ⚠️ **СТАТУС:** УТВЕРЖДЕНО. Изменения только через RFC.

## 1. ИКР (Идеальный Конечный Результат)

**ИКР-1 (Функциональный):** Система сама продвигает задачу вперёд, автоматически выявляет имитацию прогресса, локально исправляет ошибки, и только при реальной неоднозначности привлекает пользователя.

**ИКР-2 (Безопасностный):** Система сама предотвращает выполнение вредоносного кода, не требуя внешнего контроля за пределами sandbox.

**Анти-ИКР:** Система НИКОГДА не должна выдавать DONE без реального результата, позволять контролёру менять артефакт, или смешивать функции агентов.

## 2. Архитектурные принципы

| Принцип | Реализация | Проверка |
| :--- | :--- | :--- |
| Разделение ролей | Критик=Результат, Аудитор=Процесс | Контракты исключают пересечение полей |
| Детерминизм | Метрики и триггеры — код, не LLM | Все stop-criteria детерминированы |
| Stateless агенты | Coder/Critic без истории | Протоколы не принимают trace/history |
| Безопасность по умолчанию | Sandbox = враждебная среда | Fail-closed при ошибке изоляции |
| Contract-First | Схемы утверждаются до кода | CI проверяет schema drift |
| Stub-ability | Каждый WP тестируем без LLM | Stub mode проходит все тесты |

## 3. Разрешённые противоречия (АРИЗ/ТРИЗ)

| Противоречие | Приём ТРИЗ | Решение |
| :--- | :--- | :--- |
| Контроль vs Сложность | Разделение | Критик (результат) и Аудитор (процесс) разделены во времени и пространстве |
| Быстро vs Качественно | Предварительное действие | Pre-computed metrics, Policy Engine до вызова LLM |
| Изоляция vs Производительность | Динамичность | Local sandbox (dev), Docker (prod) |
| Частый аудит vs Нагрузка | Переход в новое измерение | Триггерный аудит вместо циклического |
| Детальный лог vs Объём | Матрёшка | TraceEntry хранит хэш, полный артефакт — отдельно |

## 4. Trust Boundaries

```
[Host System] ← доверенная зона
    ↓
[Sandbox] ← враждебная зона (изоляция)
    ↓
[LLM Provider] ← внешний доверенный сервис
    ↓
[User Input] ← недоверенные данные
```

## 5. Критический путь

`WP-0` → `WP-1` → `Integration Point A` → `WP-3` → `Integration Point B`

Без завершённого WP-0 ни один другой пакет не может быть начат.

## 6. Stop Criteria

Цикл (кодер ↔ критик) завершается при:
1. `verdict = PASS` → артефакт принят → DONE
2. `requires_user = True` → эскалация → BLOCKED
3. `iteration_limit` (3–5) → эскалация → BLOCKED
4. `auditor_block` → эскалация → BLOCKED

Приоритет: `requires_user` > `auditor_block` > `iteration_limit`.
