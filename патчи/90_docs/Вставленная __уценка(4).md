R3 базу довели до замкнутого состояния. **`R3.4 Control-loop Closure`** завершён и зафиксирован.

Теперь полный контур выглядит так:

```
```

```
ResearchDOM TASK
→ execution / peer delegation
→ typed admission
→ canonical CLM / EVD / QTY
→ explicit semantic linking
→ GraphEdge
→ RelationAssessment
→ strict reasoning
   ├─ ACCEPTED / QUALIFIED
   │    → relation участвует в reasoning
   │
   ├─ INCONCLUSIVE / BLOCKED
   │    → blocking Gap
   │    → ResearchChallenge
   │    → CHALLENGE card
   │    → Q1/A1/Q2/A2
   │    → executable TASK
   │
   └─ REJECTED
        → relation lifecycle
        → ACTIVE → INVALIDATED
        → canonical EDG revision
```

Причём все три ветви теперь имеют разные владельцы решений. Observation не меняет knowledge state, assessment не мутирует graph напрямую, lifecycle reducer не пишет сам в registry, а Registry не решает допустимость перехода. Немного бюрократии, зато теперь каждый виновник будущей ошибки хотя бы известен по имени.

Что добавлено в R3.4:

- **`StrictReasoningFacade`**: новый R3-путь всегда требует текущий **`RelationAssessment`**. Старое permissive-поведение остаётся только compatibility API для R2/legacy.
- **`RelationFeedbackProjector`**: **`INCONCLUSIVE + BLOCKED`** превращается в typed **`Gap`**, затем используется уже существующий R2 путь **`Gap → ResearchChallenge → CHALLENGE`**.
- Один **`RelationAssessment`** может породить только одну challenge-ветвь. Повтор блокируется.
- Challenge проходит старый **`PlanningDialectic`**, а не новый специальный planner.
- В E2E challenge дошёл до **`TASK(capability=evidence.verify)`** и **`PlanningGate=PASS`**.
- **`REJECTED`** relation не создаёт Gap автоматически. Она идёт в lifecycle invalidation.
- **`ClaimRegistry.update_graph_edge()`** теперь является canonical L1 write boundary для revised **`GraphEdge`**.
- Проверяются revision, endpoints, edge kind и соответствие **`EDGE_STATE_CHANGED`**.
- Новый relation-generated **`Gap`** больше не остаётся эфемерным: **`Gap + ResearchChallenge`** сохраняются атомарно через существующий SQLite/UoW.
