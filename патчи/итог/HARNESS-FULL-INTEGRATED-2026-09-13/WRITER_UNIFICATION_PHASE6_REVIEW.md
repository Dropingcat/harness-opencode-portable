## Why Phase 6 was split

The live migration sources disagreed about numbering: the prose deep-work plan called Phase 6 the archive phase, while prior local work used “Phase 6” for external binding cleanup. More importantly, the supplied server snapshot did not yet contain the accepted Phase 4/5 canonical runtime/gate moves. The safe sequence was therefore:

1. preserve the supplied full snapshot as a Git baseline;
2. roll forward only the already accepted Phase 2–5 code/test artifacts;
3. perform external binding cleanup as P6A;
4. run an explicit archive-readiness gate before any destructive move.

No archive was performed while that gate remained blocked.
